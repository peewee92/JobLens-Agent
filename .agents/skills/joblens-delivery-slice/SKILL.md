# JobLens：以业务主线为中心的 SDD

1. 首先阅读根目录 `AGENTS.md`、当前 `git status`、`docs/implementation/SDD-Codex-Workbench-Pilot.md`；必要时读取目标模块的真实代码和现有 tests/evals。
2. 核对既有完成程度；尤其不能把 vNext 1.3 已通过的 MCP STDIO 本地验证当作未实现而重新循环。
3. 只选一个可观察、能产生实际业务价值的最小切片；明确目标用户、原行为、目标行为、不做项、失败边界、契约 owner 和验证方式。
4. 小 Bug 可直接修；中型及以上需求优先走 OpenSpec（**必须确认已安装和初始化**），未安装则先记录轻量需求卡，不假称运行工具。
5. 保护所有本地未提交和未跟踪文件；默认不重置、不推送、不合并、不部署、不调用收费 Provider。
6. 最小实现、针对性回归、失败例证、`git diff --check`，并输出「已实现／本轮通过／未核实」分层证据。禁止用历史验收结果充当新修改结果。
7. 遇到同一质量门重复失败超过两轮，停止无进展循环；优先回到业务主线、询问用户是否取舍。
8. 每轮沉淀 1 个技术决策、1 个可复现失败、1 段面试口述。只记录非敏感内容。

不要为展示多 Agent 而在同一工作区开多个写者。 `AGENTS.md` 的产品事实和权限约束始终优先。
