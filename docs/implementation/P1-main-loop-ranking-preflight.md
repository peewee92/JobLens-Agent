# 分析前检查岗位范围

## 需求卡

- 用户：选择一批已有岗位、准备运行目标岗位分析的人。
- 原行为：运行之后才发现部分岗位未进入排序，可能误以为已完整比较。
- 本切片：显式只读检查当前所选岗位；部分缺失时列出岗位和详情入口，全部缺失时不能启动。选择变化后需重新检查。
- 不做：不提取要求、不补生成匹配报告、不解释缺失的具体原因、不承诺预检后的事实不会变化。
- 契约：复用现有 `GET /api/match-ranking`，不新增业务数据或接口；排序结果只是当时的快照，运行仍独立重新校验。
- 失败边界：接口失败或异常响应不允许启动；既有请求重试和历史分析恢复不受预检限制。不调用模型、不修改真实数据。

## 技术决策与复现

选择复用与运行相同的默认排序查询，而不是维护另一套资格判断，缺点是无法区分每个未进入排序岗位的确切原因。可复现失败：选中没有当前有效匹配报告的岗位，检查后其出现在未参与列表；补齐报告后须重新检查。检查结果不会把缺失当成不具备能力。

## 面试口述

“我把分析前的范围检查接到了已有排序入口，展示未参与的岗位并允许用户修复；检查是只读快照，不冒充执行时的保证。正式运行仍重新校验，避免让前端缓存变成业务事实。”
