# 导入观察原文快照

## 需求卡

- 用户：重新采集、导入同一岗位后，需要保留旧岗位原文以便解释历史分析与排查采集变化。
- 原行为：`Job` 和 `JobSource` 更新为最新观察；成功导入的逐条审计记录只有身份和结果，旧的来源原文被覆盖。重复记录在同一批中也有同样问题。
- 目标：每次导入的成功条目保存该次来源原文的内部快照，含异常输入的对象也保留自身快照；同一事务提交。保持当前岗位仍代表最近导入数据，不把旧资料伪装为最新资料。现有公开导入查询不暴露快照。
- 不做：不自动回填旧记录、不恢复未知历史原文、不修改公开接口、不自动合并或选择更长的描述、不改变导入幂等或岗位分析规则。
- 边界：快照可能包含采集原文和来源字段，属于本地敏感数据；不应写入日志或普通 API。旧记录是空值，不能用当前来源填充假历史。降级迁移删除快照列，应先备份数据库；不对用户真实库执行迁移。
- 契约 owner：内部导入仓库和数据库迁移；公开响应形状保持不变。

## 验证与面试口述

- 可复现失败：同一批先导入完整描述、再导入同一岗位的短描述时，`JobSource.source_raw` 和 `Job.description` 均变成第二条；旧实现的第一条导入审计无法还原第一条原文。
- 验证：真实 SQLite 与 HTTP 测试覆盖同批两次观察、跨批重新导入和错误对象，确认各自快照独立、当前岗位仍为第二次观察，公共导入详情不含敏感标记。相关导入、仓库和事务测试 32 项通过，其他导入、迁移、就绪和查询测试 27 项通过。
- 迁移：对以前构造的隔离示例库进行只读复制后迁移；37 张旧表数据保持一致，完整性与外键检查通过，2 条旧审计记录的快照均为 NULL。另用独立数据库验证从旧版本升级、旧记录为空和降级后记录保留；未迁移真实数据库。
- 面试口述：当前状态和历史观察是不同事实。系统记录每次观察原文但不以长度推断哪版岗位真实有效；历史缺失标记为未知，而不是用最新数据伪造历史。用户界面和分析工作流暂不能浏览或恢复这些快照。
- 后续风险：重新导入的较短或不完整描述仍会成为当前岗位描述，本切片只确保今后的旧原文可追溯，并未完成自动保留旧版本或供用户比较的功能；此问题应结合来源有效性、用户确认和旧分析过期策略单独设计。
