# 采集来源记录时间

## 需求卡

- 用户与问题：导入岗位后需要核实信息是否仍然可用；岗位详情原来只显示采集时间，导入逐条列表没有当前来源记录时间。
- 实现：岗位详情 API 返回当前选中来源保存的 `lastSeenAt`，导入逐条结果和岗位详情展示它；缺失或查询失败时显示未知。共享 Job 契约增加可空字段，旧客户端可忽略。
- 边界：这是来源记录的当前值，采集端缺失时可能用报告时间或系统记录时间补齐，也不保证是所有历史观察的最大值。导入列表显示当前来源，不冒充该批次历史观察。时间早不代表岗位关闭，系统不据此过滤、改写状态或调用模型。
- 不做：用户手动标记失效、历史观察比较和恢复、重新采集以及现有来源覆盖策略；这些能力仍需单独实现。
- 可复现问题：仓库实际已有选中来源的 `last_seen_at`，但详情 API 没返回，用户只能看到可能不同的 `collectedAt`，无法区分两种记录。
- 技术决定：只复用现有来源字段，不增加第二份时间状态；不把原始来源对象返回到公共接口。

## 验证与面试口述

- 隔离 SQLite 中测试选中来源的观察时间与采集时间不同时仍分别返回；HTTP 响应符合共享契约且不暴露原始来源字段。相关后端测试 23 项通过。
- 前端 291 项测试与类型检查通过；浏览器使用隔离合成库查看岗位详情和两条导入记录，实际显示来源记录时间及“不代表仍在招聘”的说明。
- 面试口述：时间字段是来源记录而非招聘网站实时状态；旧数据可能由报告或系统时间补齐，因此页面明确提示其局限，历史结果和推荐规则不因此被改写。
