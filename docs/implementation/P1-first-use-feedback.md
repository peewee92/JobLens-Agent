# JobLens 首次使用：真人反馈与修复记录

## UX-01 / PROFILE-01 · 解析失败后无法轻松继续

- 来源：首次使用者在本地正式版上传简历并授权，看到“模型没有返回可用草稿”，手动路径又打开了学历、工作年限、技能和经历简称等完整表单。用户明确反馈填写负担过重。这里仅记录症状，不保留简历内容、个人信息、路径和模型输出。
- 证据：只读查询本地运行记录中的错误分类；有一笔结构化返回被“经历引文找不到对应简历原文”拦截，并未创建职业背景。未读取原文、未重发原文件，也无法判断原回复中有多少条其他经历可以保留。
- 改动 A：首次空白状态提供快速填写，只需职业定位、一段亲历事实和（缺失时）目标岗位。在填写处明确确认，不需要模型，也不自动写入。补证、已有草稿和详细编辑保持原路径。
- 改动 B：本地授权提取在引用不匹配时，只有还能找到至少一条可信经历才返回不完整草稿；删掉不对应的经历和依赖它的技能。保留的经历直接展示原文，不用模型摘要拼接。仍由本人核对并保存；没有可信经历、重复键或失效关联时依旧失败。远程自带模型和正式评估维持严格校验。接口可选字段 `sourceRecovery` 仅在部分恢复时出现，并且只有这类结果允许空技能列表。
- 可复现失败：合成简历包含“负责 Python 和 FastAPI 服务开发”，模拟模型给出一条原句和一条不存在的 MCP 经历。旧校验整份拒绝；新本地路径仅显示前者，且依赖后者的技能不进入草稿。将两条都改成原文不存在的句子，仍失败并提供快速填写。
- 技术决策：部分恢复属于本地交互策略，不改变引文精确对齐规则，也不改变任何已确认资料或模型用量。
- 面试口述：真人并不需要理解为什么模型没返回；他需要在不牺牲真实性的前提下继续。我把完整拒绝拆成有可靠事实和无可靠事实两条路，再分别验证草稿、确认和保存都不会被绕过。

## UX-02 · 区分“已有相关经历”和“能覆盖全部要求”

- 来源：Computer Use 对照早先获准留下的合成验收记录。历史匹配把 Agent 应用经验判为部分支持；准备页却显示暂无可引用经历。模型说明指出样本能证明做过 Agent，但不证明工具调用和失败处理。
- 修复：差距卡与面试提示使用同一份已绑定报告的部分支持标记；只匹配明确的岗位、原文版本、用户资料版本、求职意向版本和匹配策略。引用跳到该历史报告的匹配区。读取失败或不一致时不借用新报告，也不重算。
- 复验：打开同一份历史准备材料，看到 Agent 要求“只覆盖部分”，Docker 加分项仍显示没有可直接引用的经历；点击链接进入原报告的“部分支持”区域。不升级技能或匹配结论。

## 本轮验证证据

- 浏览器，合成输入和模拟模型：文字计划先显示“尚未发送”；一次混合引文仅保留 1 条原句、排除 1 条无依据经历及其 1 项技能。未确认保存即刷新，背景仍为空。
- 浏览器，模拟全不匹配：错误旁点击“快速填写”，页面只有职业定位、经历和目标岗位三个输入。明确确认后保存 1 份背景、1 条经历、0 项技能和 1 个求职意向，点击“去添加岗位”到第 2 步。没有重试模型。详细编辑仍可选。
- 文件接口，合成 DOCX：后端真实解析出 79 字符并返回单次调用计划，不发送模型。当前 Chrome 扩展未开放自动附加本地文件；界面回归用的是粘贴文字，同一模型计划及恢复分支由两条输入路径共享。
- 历史准备页回放的是此前真实模型对合成资料产生的结果，不是本轮新付费调用。

## REQ-03 · 同一句的选做技能被当成硬要求

- 来源：公开招聘改写保留集 `public-embedded-firmware`，来自 [嵌入式系统工程师招聘发布页](https://job-boards.greenhouse.io/bevicareers/jobs/4471140009)。这是向生产校验器提供结构化模拟输出的回放，不是本轮在线输出。
- 可复现：嵌入式 C/C++ 和 RTOS 环境为必需，括号里 FreeRTOS 只是优势、不强制。给校验器模拟模型把 FreeRTOS 归为必需（整句或只引用名称）时，两种均被旧校验保留为必需。
- 验收：本地个人分析中，仅将原文明确标为有优势、但不强制的同一技能改为“优先”；相邻的硬要求、原文、证据片段和已有提取记录不变。只有独立技能行或其已绑定证据中的无歧义括号才适用；不从职位名称或其他行推断，不覆盖非技能条件。正式模型评估仍使用原来的冻结策略。
- 契约归属：提取应用层在版本化本地工作流内修正 `JobRequirement.importance` 的已有枚举，不新增字段，不移除人工确认。记录实际修复索引供追踪；无新外部调用。
- 复验：在独立 SQLite 通过 Computer Use 粘贴同一条脱敏岗位改写，先保存、不调模型；勾选才启用单次提取。模拟传输故意把两项都发成“必须”，实际页面和保存结果为 C/C++「必须」、FreeRTOS「优先」，证据片段仍显示其“不强制”。只有一条模拟调用回执，追踪记录只修正后一项；没有保存用户背景或新增在线请求。模拟输出只针对两个关键条目，不代表该岗位的模型提取已完整通过。
- 技术决策：仅在能绑定到同一技能的确切原文时修正重要性，不因为整行里出现“有优势”就降低其他条目的重要性。
- 面试口述：我用公开岗位构造可重复的错误回包，先证明旧版会制造假硬门槛，再确认修复恢复候选人的可比较性且不改写硬要求。

## UX-03 · 岗位空状态指向不存在的按钮

- 来源：同一 Computer Use 复验。首次打开岗位，提示寻找“分析岗位要求”，实际本地模式只有“授权并提取一次”，且勾选之前不可点。
- 修复：新本地空状态明确先查看调用范围、再决定是否授权一次；描述不足仍引导补全文本，读取失败或岗位失效不再指向不可操作的提取。离线入口保留自己的名称。
- 复验：在同一验收库导入第二个仍未提取的对照岗位，页面同时显示新指引、未勾选且禁用的真实按钮；没有第二条调用回执。

## EVAL-01 · 已标对的一行不能掩盖同技能错误硬门槛

- 可复现：同一技能在一条候选输出被评为“优先”，又在另一条被评为“必需”。若只检查期望标签有没有出现，两行同时存在也会错误通过。本次新建的小样本只读核对把它单列为重要性冲突，不改旧版正式门禁。
- 复验：测试覆盖未测、失败、结果未知、错绑原文与回执、遗漏、冲突、不该出现的能力及无依据引文。对暂未调用的真实来源库，报告 4 条未测且无回执；对复制库用生产接口注入已有合成固件回包，报告 3 条未测、固件缺少 Python，FreeRTOS 未再误标为必需。两次评分本身均不修改数据库、不发请求；没有把复制库回放当成在线模型输出。
- 技术决策：评分只接收独立、无简历的评估库，并绑到同一份原文、回执、提取版本和追踪，不能使用最新结果填补缺失的真实验收。
- 面试口述：我把小样本诊断与正式门禁分开。一次模型请求结束不等于产品判断正确；既要抓漏项，也要抓同样重要的额外误报，再让人核对替代条件。

## 2026-11-18 · 真实模型复验（4 条脱敏公开岗位）

- 范围：`qwen3.8-flash`，在无职业背景的独立 SQLite，每条岗位一次。4 次真实 HTTPS 请求均为 HTTP 200，均保存了可核对的要求，未重试、未发送个人简历。应用端单次回执绑定岗位原文和版本；本地审计另外记录了真实传输及模型返回标识是否存在，不保留密钥、具体业务空间或服务商请求标识到仓库。
- 费用：按[北京公开定价](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)，本轮共 5,337 输入、2,366 输出 token，按非缓存单价估算 **¥0.0106578**（不是账单）。请求仅含岗位文本及固定提取提示，不使用联网、工具或显式缓存；按模型最大输入和每次 4,096 的输出上限计算，4 次最坏约 ¥3.22，在人民币 5 元授权内。
- 预设精确标签：1 条通过、3 条有差异，四条的原文引文检查均通过。人工逐条核对如下，保留原判断，不事后修改冻结门禁。四条不代表总体成功率。

### REQ-04 · 保留替代资格，分开居住地和工作授权

- 来源：真实云数据与射频岗位回包。云数据的学历替代漏判被精确标签检查漏过；在浏览器从首页打开岗位详情，实际看到「优先 学历」和一条合并的居住/工作授权。射频的「学历或等效实践」本来也不应作为单一路径的硬学历。
- 需求卡：用户核对岗位时，原文明示「学历或同等实践」只是一道资格条件，不独立要求学历，也不能降级成加分；在确切的并列句中把居住与工作授权分别呈现，明确由用户分别核实。只对原文唯一且能绑定的明确句式生效。优先段落、歧义表达、旧记录、正式门禁、模型提示和共享接口保持不变。
- 修复：本地提取版本记录拆分或保留替代资格的原因；可核对的两段仍是原文逐字子串，不增加新资格。缺少可靠事实时输出待核实，不能从求职地点、已确认经历中的字面提及或学历名称推断。
- 回归：在新隔离库通过完整应用接口离线重放这 4 条实际回包（不是新调用）；四条均能保存，分别为 6、10、10、6 行，云数据增加 1 行。两条学历替代均以单一资格项保留，云数据居住与工作授权分为两条；超过提取条数上限时保留原并列句。模型输出与正式门禁不变，原资料未被改写。
- 技术决策 / 面试口述：我保留精确标签作为可复现的诊断，让人工核对发现正例里的真问题。产品修复的是硬资格的逻辑，不是把模型的措辞改成和标准答案逐字相同。

- 同一真实云数据结果的 `Build transformations`、`investigate data-quality problems` 是工作内容，不是投递前置条件。新版个人提取仍保留职责和逐项经历对照，但单凭职责没有证据，不再把基础资格从满足降成待核实；明确的任职约束仍独立处理。冻结版及存量报告不重写。
