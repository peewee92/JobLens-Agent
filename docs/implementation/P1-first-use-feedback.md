# JobLens 首次使用：真人反馈与修复记录

## UX-01 / PROFILE-01 · 解析失败后无法轻松继续

- 来源：首次使用者在本地正式版上传简历并授权，看到“模型没有返回可用草稿”，手动路径又打开了学历、工作年限、技能和经历简称等完整表单。用户明确反馈填写负担过重。这里仅记录症状，不保留简历内容、个人信息、路径和模型输出。
- 证据：只读查询本地运行记录中的错误分类；有一笔结构化返回被“经历引文找不到对应简历原文”拦截，并未创建职业背景。未读取原文、未重发原文件，也无法判断原回复中有多少条其他经历可以保留。
- 改动 A：首次空白状态提供快速填写，只需职业定位、一段亲历事实和（缺失时）目标岗位。在填写处明确确认，不需要模型，也不自动写入。补证、已有草稿和详细编辑保持原路径。
- 改动 B：本地授权提取在引用不匹配时，只有还能找到至少一条可信经历才返回不完整草稿；删掉不对应的经历和依赖它的技能。保留的经历直接展示原文，不用模型摘要拼接。仍由本人核对并保存；没有可信经历、重复键或失效关联时依旧失败。远程自带模型和正式评估维持严格校验。接口可选字段 `sourceRecovery` 仅在部分恢复时出现，并且只有这类结果允许空技能列表。
- 可复现失败：合成简历包含“负责 Python 和 FastAPI 服务开发”，模拟模型给出一条原句和一条不存在的 MCP 经历。旧校验整份拒绝；新本地路径仅显示前者，且依赖后者的技能不进入草稿。将两条都改成原文不存在的句子，仍失败并提供快速填写。
- 技术决策：部分恢复属于本地交互策略，不改变引文精确对齐规则，也不改变任何已确认资料或模型用量。
- 面试口述：真人并不需要理解为什么模型没返回；他需要在不牺牲真实性的前提下继续。我把完整拒绝拆成有可靠事实和无可靠事实两条路，再分别验证草稿、确认和保存都不会被绕过。
