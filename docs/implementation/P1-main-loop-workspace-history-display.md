# 工作区历史行动与事实显示切片

## 需求卡

- 用户：已经更新分析，并回到已有求职工作区的人。
- 原问题：新旧分析产生的相似行动混排；事实确认后，即使当前分析使用了更新后的资料，页面仍统一提示更新分析。
- 本次行为：按保存的分析结果标识分组当前行动和更早或来源不明的行动；保留旧行动及其原有状态。事实卡只描述确认版本与分析输入版本的先后关系，不保证后续编辑仍保留该事实。
- 不做：合并、删除或自动完成行动；不推断能力变化；不调用模型；不修改业务数据或接口契约。
- 失败边界：缺少来源标识的行动归入较早或来源不明；缺少可比较版本时不宣称已被分析使用；历史工作区无当前分析时维持原有列表。
- 契约归属：沿用既有工作区、行动、事实提案及保存的准备材料接口，仅调整网页展示。
- 验证：行动分组和版本比较单元测试、网页类型检查及构建；浏览器实际交互仍需另行核验。

## 技术决策、失败例证与面试表达

- 决策：不根据文字相似度合并行动，而按不可变分析结果标识分组，避免丢失人工进度或抹去溯源。
- 可复现问题：在已有工作区确认新事实，创建并执行新的分析，然后重新打开工作区；旧版会混排两次分析的相似行动，并仍提示已确认事实需要更新分析。
- 面试表达：我们将长期人工行动和单次分析分开；更新后保留历史来源与状态，通过明确分组消除混淆，而不是把相似任务视为同一任务。资料版本只能说明分析输入的时间关系，不能证明用户后续编辑保留了每条事实。

## 浏览器核验（隔离合成数据）

使用此前端到端测试生成的合成 SQLite 数据库副本和本地生产构建，打开已更新分析的工作区：当前分析两项待办显示在主区域；展开历史区域后可见较早分析的两项相似待办及一项已完成的无来源行动，来源链接和完成状态保留。已确认事实显示确认资料 v2 与分析资料 v2，不再显示针对该事实的更新提示。此次验证仅覆盖该页面的显示与展开交互，不代表三条完整业务路径已验收。
