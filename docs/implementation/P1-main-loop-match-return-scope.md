# 生成匹配后保留原岗位范围

## 需求卡

- 用户：核对资料后，从预检结果进入岗位详情并重新生成匹配报告的人。
- 原行为：报告生成成功后页面清除全部查询参数，连同返回分析所需的岗位范围一起丢失。
- 目标：生成成功后只返回经过校验的岗位详情地址，保留原批次范围；旧报告标识不沿用；用户可返回分析并重新检查。
- 不做：不自动启动另一轮分析，不改变报告生成规则或开放真实模型调用。
- 失败边界：匹配失败时留在原页面并展示错误；报告成功后才更新页面。返回地址只由岗位页面按合法范围构造，不接受来自外部的任意地址。

## 决策和复现

将页面已验证的返回地址传给匹配组件，而不是在组件里复制查询参数解析。隔离数据复现：先更新资料，再对一个缺少报告的岗位生成离线报告，页面保留返回入口；回到两岗位范围后重新检查，新报告进入排序，另一过期报告仍单独提示。

## 面试口述

“我修复了一个看似页面跳转、实则会中断用户任务的缺陷：生成报告不能清空当前批次。范围只是导航上下文；报告的有效性仍由后端重新检查。”
