# 从岗位核对返回原分析范围

## 需求卡

- 用户：批量检查后前往某个岗位核对信息的人。
- 原行为：详情页没有返回原分析范围的入口，回到分析页可能重新选中默认岗位。
- 目标：预检的岗位详情链接带上原范围，详情页提供返回按钮；返回时重新获取每个岗位并重新检查，不缓存旧判断。
- 不做：不保存第二套运行状态、不自动发起分析或模型调用，不以返回范围代替服务端运行恢复。
- 失败边界：范围最多 50 个、不得重复或为空；任何岗位读取失败时不静默缩小或替换范围。返回链接由本地路径生成，不接受任意重定向地址。未完成的本地请求优先恢复，旧的已无待处理请求不会覆盖明确的岗位范围。

## 技术决策和复现

范围放在本地页面地址中，而不是只保存在浏览器存储；因此刷新或打开链接时仍可带回。同一详情页查看历史报告也保留范围。复现：选择两个岗位，检查后进入其中一个岗位，点击“返回所选岗位分析”，两个选择仍在，运行按钮保持禁用直到重新检查。

## 面试口述

“我把修复导航携带的岗位范围和运行状态分开：页面地址保存选择，服务端仍是运行状态权威。返回时重新查岗位和预检，避免旧判断被当成当前事实。”
