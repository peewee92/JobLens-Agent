# 要求审核决定：原子固定证据（第一步）

- 问题：已有审核决定只存汇总和指纹，读取时依赖岗位当前描述；样本发生变化后无法完整重建当时的审核内容，并可能使无关岗位的基线同时失效。
- 本步：新建最终决定时，在 SQLite 短写事务内读取当前批次、校验审核条件，并与决定一并保存版本化审核证据快照及其完整性摘要。快照包含批次、岗位原文、提取要求、人工判断和版本；不调用模型。
- 边界：不回填或伪造旧决定快照；不改变现有基线放行策略，不声称已解决连带阻断。下一步必须验证快照完整性并明确版本兼容和旧记录策略后，才考虑按冻结的模型版本使用基线。
- 验收：迁移旧库副本保留原决定且快照为空；新决定有完整快照，后续岗位改变不改变快照；决策时样本失效则拒绝；提交失败同时回滚；并发更改不能落在校验与提交之间。
- 技术决策：一次写锁下读取及写入，不让外部模型或长时间人工操作占用事务。指纹用于检测内容变化，不声称防篡改或替代人工审核。
- 可复现风险：旧实现先查询再进入写事务，查询与提交之间样本可变化；旧指纹无法还原原始岗位描述及全部要求。
- 面试口述：把审核决定和当时证据固定在同一短事务中，旧记录无快照则保留原有保守策略，不将历史推测为事实。

## 本轮验证

- 真实 SQLite 测试在审核写事务持锁时注入另一个写入，后者被拒绝；随后决定和 20 个案例的原文、要求、人工审核及执行记录快照同时保存，摘要可以复算。
- 决定后修改岗位描述，已保存快照保持不变；决定前样本失效则拒绝；模拟提交失败时不留下部分决定。现行基线仍按旧规则判断。
- 迁移测试从 0029 升级与降级，旧决定保留且新字段为空；另将 72 条合成岗位数据库副本升级至 0030。没有操作真实数据库。摘要是完整性检查，不是认证签名。
- 该步没有提供审核快照公开查看界面，也没有完成基线使用新快照的策略；实际使用数据库需先经备份与迁移流程，不能仅凭本次副本测试推断生产数据升级完成。
