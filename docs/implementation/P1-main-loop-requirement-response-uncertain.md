# 岗位要求分析响应不确定时先核对

- 问题：单岗位或批量要求分析可能已保存结果但响应丢失，原页面仍称“分析失败”并允许直接重试。
- 本轮：网络或响应解析异常、HTTP 408 和 5xx 显示结果不确定并要求先刷新核对；未授权等明确客户端错误仍保留具体原因。单岗位按钮在不确定时禁用，批量入口隐藏重试控件。不调用模型或改变服务端契约。
- 真实 SQLite 故障验证：在隔离数据库副本使用离线替身，本地代理将单岗位要求分析转发给真实后端，等待 201 后向页面返回 503。浏览器看到不确定提示及禁用按钮；点击刷新后看到新的要求分析时间和历史匹配已过期。替身结果不等同正式质量验收。批量入口使用同一状态策略，但本次未在浏览器注入批量故障。
- 测试边界：网页类型检查、组件测试和网页全量测试验证呈现及分类；不能由此推断所有网络情况或服务端并发已处理。
- 服务端方案拆分：现有匹配报告用例先在事务外计算，再独立提交报告；仅复用运行租约而不在报告写入事务内校验令牌，会允许过期执行者仍写入。要解决跨标签页和崩溃，需将请求摘要、步骤领取与报告引用纳入统一持久化，并在报告保存的同一短事务中验证领取并记录步骤结果；同命令重放读取已保存结果，不同内容冲突。模型结果未知不得自动再次付费。该机制尚未实现，本轮不把页面限制说成幂等。
- 可复现失败：代理丢失成功响应后，旧页面错误提示“分析失败，请重试”，可能产生第二份提取记录。
- 技术决策：无法断定已提交或回滚时，提示核对已保存事实，而不是将网络错误转为业务失败。
- 面试口述：读取失败不等于后台事务失败；页面先隔离未知结果，服务端仍需原子保存业务结果与命令回执，才能处理进程崩溃和并发。
