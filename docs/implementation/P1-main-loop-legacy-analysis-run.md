# 历史工作区：接入可恢复的受控分析

## 需求卡

- 目标：未关联保存分析的历史工作区，用户明确启动后使用同一运行存储、规则匹配步骤和人工确认，产生可保存的新分析，不伪造旧分析或比较结果。
- 约束：读取预检摘要后再次检查；固定工作区身份、岗位、资料、意向、要求和匹配版本；关联状态变化视为过期。仅执行零模型规则路径，需模型时保留明确阻断。原请求同内容重放不重复执行；报告和步骤同事务提交，重启由用户继续。
- 契约：新增历史工作区启动命令和运行来源标识；旧分析与时间线保持不变。界面仅在有明确预检后由用户点击启动，并保留原请求以应对网络不确定。
- 验收：真实 SQLite/HTTP 测试覆盖正常分析并保存结果、相同及冲突命令、并发、事实/工作区关联变化、保存失败与恢复、模型缺口零调用。浏览器验证用户入口。OpenSpec 未安装，以此需求卡执行。

## 本轮结果与证据

- 历史工作区启动命令绑定工作区标识和预检摘要，单独保存来源字段，不冒充已有分析；重新预检发现变化会拒绝启动。现有运行继续使用 SQLite 修订、租约、固定事实校验和同事务报告/步骤保存。需语义模型的步骤保留阻断，不持有可用 Provider。
- 同命令重放不重新执行，不同内容冲突；浏览器请求发送前保存标识和内容，刷新不自动发送。不能以这个客户端本地日志代替服务端权威状态。
- 真实 HTTP/隔离 SQLite 测试覆盖规则分析并保存、重复与不同内容、两个并发请求、过期预检、关联变化、报告插入失败后继续、失败后关联变化、模型缺口和共享 Schema；与已有受控更新测试合计 21 项通过。网页 234 项测试、类型检查和生产构建通过。
- 浏览器使用隔离合成数据库，实际从历史工作区启动规则分析，确认目标，打开保存结果，并点击开始执行复用原工作区；不代表全部真实用户闭环或其他失败路径已在浏览器完成。
- 故障复现：触发数据库报告插入失败，接口报告保存不确定，运行步骤仍为进行中且没有部分报告；解除故障后明确继续，得到唯一报告。面试说明：计算在事务外，短事务中校验事实并原子提交步骤与报告；执行租约和命令摘要解决不同层面的并发与重放问题。
- 未解决：真实模型授权与计量、浏览器完整正常/证据不足/故障恢复验收；历史原分析不存在时不提供伪造的新旧比较。
- 浏览器再次打开复用后的工作区，确认新材料引用正确、原行动仍在；同时发现新旧分析会各自生成相同描述的待办，页面可能同时展示重复行动，且已纳入新分析的事实卡仍提示更新。它们是后续用户体验/状态解释问题，不应删除旧进度或把本次验证称为完整闭环。
- 后端全量回归 1630 项通过；运行开始后补充了计算中关联变化和不完整关联的保护，最终版本另以历史运行及预检 14 项回归通过。尚未把全量结果等同于三条用户路径的浏览器验收。
