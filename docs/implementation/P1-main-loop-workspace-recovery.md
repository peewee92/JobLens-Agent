# 主闭环 5C-3a：统一更新入口与人工进度请求恢复

## 需求卡（2026-10-27）

- 用户：已经有保存分析和目标工作区，需要记录人工行动/投递结果，并在新事实后更新分析。
- 原行为：工作台/工作区更新入口间接；事实确认旁仍突出旧单岗位重匹配。投递状态每次点击生成新幂等标识，行动请求未暂存；丢响应、刷新后不能明确重试原请求。
- 目标：入口统一指向相应保存结果的限定范围更新预检。人工状态/行动命令发送前保存，刷新只读恢复，显式重试沿用原内容；明确成功才清除。冲突先核对服务端，不用新命令覆盖未知请求。
- 边界：不新增业务进度库、不自动重发、不自动改职业事实、不调用模型、不修改真实数据库。复用现有后端工作单元、投递状态幂等事件和行动单向状态迁移。
- 决策：浏览器仅保存待确认传输命令，服务端仍是唯一事实源。投递状态使用已有幂等标识；行动沿用已有单向迁移/目标状态重放（不增加无业务收益的第二套命令表）。不同标签页靠服务端条件更新保障，不宣称 localStorage 是锁。
- 验收：断网/丢响应原请求保留、刷新零发送、原请求成功重试只记一次事件、冲突不覆盖、存储不可用零发送、返回成功但身份错误不清除、旧请求清理不误删新请求；浏览器实际走正常进度、刷新恢复和入口。
- 契约归属：既有投递/行动接口形状不变；新增网页内部命令类型与恢复提示。OpenSpec 未安装，使用此卡。
- 不做：本切片不完成通用模型授权计量和全部端到端验收；旧单岗位 API 权限/费用边界另做审计，不以隐藏按钮替代。
