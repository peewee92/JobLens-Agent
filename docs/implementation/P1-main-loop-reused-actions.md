# 主业务闭环：正确显示复用的行动

## 需求卡

- 用户：把内容相同的新分析应用到已有工作区，期望继续看到原有行动和进度。
- 原问题：后端按材料内容复用行动并保留原创建来源，工作区却仅按创建来源分组，导致当前分析复用的行动被藏到较早行动中。
- 目标：复用已有执行回执核对当前分析、工作区和行动标识，将被复用行动显示在当前区域，保留原始来源链接与进度；当前分析单独新增的行动仍按来源显示。
- 不做：不创建重复行动、不重写来源、不修改业务契约或自动完成行动。
- 失败边界：读取回执失败或结果与工作区不一致时，保留所有行动，按原创建来源分组并显示无法核对的提示。
- 验证：真实 SQLite 后端测试验证新分析复用材料；前端测试验证分组、来源和已完成状态。浏览器使用隔离数据库副本，人工构造原来源与执行回执不一致的复用夹具，验证页面展示和原来源链接；这不是完整端到端复用流程验证。

## 工程决策与口述

行动创建来源和当前分析使用关系是两种不同事实，前者不能覆盖；后者已有执行回执即可证明，不必增加第二套业务状态。可复现问题：两次分析材料相同，第二次复用第一次行动；旧页面会显示当前分析无行动，尽管执行回执包含它们。
