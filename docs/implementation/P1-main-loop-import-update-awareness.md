# 重复采集后提醒核对岗位

- 用户问题：重复导入会更新当前岗位，较短或不完整的描述可能替换原描述；用户只看到“信息已更新”的数量，不一定知道需要核对哪个岗位。
- 本轮：导入结果按岗位去重显示更新提示，明确新采集可能替换当前信息，提供当前岗位详情入口；逐条处理结果展示当前岗位名称。岗位读取失败时保留标识作为入口，不凭空生成名称。
- 边界：本批次是否有 `updated` 仅说明已有记录被处理，不证明描述一定变化；当前名称不代表历史名称。此提示不自动选择更长描述、不恢复旧数据、不展示原始私有快照，也不判定岗位是否仍在招聘。历史原文比较与用户确认恢复仍未实现。
- 验证：类型检查及网页 298 项测试通过，覆盖重复岗位去重、空结果和名称缺失。实际浏览器使用经迁移的隔离 SQLite，导入同一合成岗位的完整与短描述后，显示一条更新提示；展开链接进入岗位详情，看到短描述和重新采集提示。没有调用模型或修改真实求职记录。
- 失败复现：同一导入批次的第二条短描述成为当前岗位描述，历史导入记录的两行原先均只显示“查看岗位”，无法直接识别岗位并容易忽略变化。
- 技术决策：展示不确定性和明确的核对入口，而不是以描述长度擅自替用户决定哪个版本真实。
- 面试口述：把导入观察、当前岗位和历史分析区分开；显示提示不等于完成版本比较，后续仍需要可信的历史比较与明确选择机制。
