# 主业务闭环：导入批次逐岗位就绪检查

## 需求卡

- 用户：导入岗位后，想处理该批次中所有具备输入条件的岗位。
- 原问题：导入页面把人工评审抽样接口的前 20 个岗位当作全量就绪名单，样本之外即使就绪也无法进入匹配；个人资料未就绪或检查失败的岗位可能在数量与列表之间表现不一致。
- 行为：复用已有逐岗位只读输入预检，按实际岗位分类；已有有效匹配、可匹配、岗位要求未就绪、未能确认互不混淆。读取失败不当作就绪。
- 不做：不改人工评审采样规则、接口契约或业务记录，不触发模型调用；当前页面每个岗位会有一次额外只读检查，大批量性能需后续测量。
- 失败边界：排序不可读取时不宣称岗位已完成或可匹配；无法读取预检时列为待核实；单个岗位检查失败不影响其他岗位分类。

## 验证与口述

隔离合成数据库中构造一个不在评审前 20 个样本内、但自身输入已就绪的岗位；对比评审接口与该岗位预检后，浏览器导入页显示该岗位及另一就绪岗位均可匹配。测试覆盖 51 岗位分类和缺失数据。完整 51 岗位浏览器分批交互尚未验证。

技术决策：评审样本与产品输入就绪属于不同事实，不能用有界抽样代替逐岗位检查。可复现问题：第 21 个就绪岗位不在 `reviewableJobIds` 中，旧页面将其遗漏。
