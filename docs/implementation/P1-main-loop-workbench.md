# 主闭环 4B：只读任务工作台

## 需求卡与完成标准

- 用户：已经拥有职业资料、岗位或分析，需要刷新后找到当前任务和下一步。
- 原行为：首页是固定介绍页，下一步不随真实记录变化。
- 目标：首页四区展示准备情况、最近运行/原分析、目标工作区、最近事实变化；一个主要按钮。新增 GET `/api/v1/workbench`，只查询现有权威记录，不保存第二套进度、不重新排序或调用模型。旧分析没有快照时明确说明。
- 有界展示：最近运行、最多 5 个工作区、最多 10 条变化；汇总数量不等于岗位数据或模型结果已验收。
- 不做：更新分析算法、后台调度、付费调用、资料自动确认、自由对话新流程。
- 验收：空数据/资料不完整/等待确认/保存分析/已有工作区/资料变化的下一步；真实 SQLite 无读写副作用；Python/共享契约；实际首页浏览与链接。
- OpenSpec 未安装且未初始化，使用轻量卡；保护当前未提交工作。下一阶段为反馈事务与限定范围更新。

## 实现与本轮证据

- `GetWorkbenchUseCase` 只从查询结果推导下一步；`SqlAlchemyWorkbenchQuery` 用一个只读快照汇总当前资料、最近运行、最多 5 个本地用户工作区和最多 10 条变化。没有新表、进度字段、排序算法或模型调用。
- 输入问题复用已有职业上下文确认规则；当前分析引用同一运行/保存结果，目标区引用原工作区。结果过期时保留旧材料并提示核对；没有保存原材料的旧运行不伪造链接。
- 执行目标数量从完整关联记录计算，不把最多 5 个展示项当成全量事实。岗位导入数量只表示已有记录，不代表要求已就绪或岗位仍在招聘。
- 数据库读取失败返回可重试的 503，不将错误包装成“空工作台”。历史及工作区入口持续可用。
- 后端全量 1552 passed；网页 201 passed，TypeScript 与生产构建通过。包含真实 SQLite/API 无写入检查、空资料、等待确认、保存分析、开始执行、资料变化、历史无产物、数据库失败及契约一致性测试。
- Chrome 实际查看首页四区；主要按钮进入既有工作区，材料仍引用原分析；临时演示库增加不完整 v2 资料后，首页展示缺少真实经历/技能关联、提示旧结果过期，同时保留两个工作区和 v1 原始分析入口。
- 验收日志及浏览器页面文本：`/tmp/joblens-start-execution.9zW5Em`。截图接口多次超时，本轮没有声称取得或完成截图视觉验收；已通过真实浏览器文本与交互验证。

### 技术决策

工作台是权威事实的只读投影，不维护“第几步完成”的持久化字段。下一步可以随资料版本、运行状态和人工行动变化而变化，不会出现主页进度与实际工作区各自为政。资料就绪不等于岗位报告有效，具体预检仍由现有执行入口负责。

### 可复现失败

隔离测试中令查询抛出数据库异常，GET 预期 503、明确修复入口且不返回 SQL 或文件路径。另将旧运行的完整产物设为空，首页只显示历史状态而不伪造准备材料。见 `test_workbench.py`。

### 面试口述

我把首页从静态介绍改成任务工作台，但没有新建产品状态机：资料、运行、工作区分别仍是各自事实源。首页只有只读汇总和下一步建议，真正写入沿用既有应用服务；刷新页面不会意外继续执行或产生模型费用。

## 后续边界

反馈事实确认的原子事务、按固定岗位范围更新分析和新旧结果比较仍属于阶段 5。首页“准备更新”只提供事实变化入口，不宣称已实现自动再分析。真实新岗位验证须单独授权。

最终针对性回归：13 passed（4A + 4B）。追加覆盖部分命令合并后保持用户原确认顺序，以及已有工作区不能遮盖最近运行的明确阻断；全量 1552 项记录与最终针对性记录分别保留，不混作新增案例总数。
