# 导入批次：记录与岗位身份分开

- 问题：同一批导入可以先新增再更新同一个岗位，服务端保留两条审计记录并指向同一个岗位。原页面按记录数量统计待处理岗位，可能重复预检、重复展示，并使一份报告无法完成两个岗位的进度。
- 目标：处理、匹配、排序和进度按不同岗位身份计算；逐条结果仍按原始记录显示，新建／更新数量不改。明确告诉用户重复记录并非多个岗位。
- 不做：不更改导入身份规则或记录，不删除数据，不改变排序和匹配算法。
- 验证：真实导入接口构造同一岗位的两条记录；前端测试覆盖去重、无岗位记录和顺序；隔离浏览器展示两条记录、一个岗位和一个待处理入口。

## 岗位描述不足的修复提示

- 问题：描述不足 40 字符时分析按钮被禁用，但导入页和详情页仍要求用户点击该按钮。
- 处理：两处依据同一长度判断，提示重新采集完整职责和任职要求；无法读取岗位详情时不把未知描述误判为不足。保留分析按钮的原有启用规则，不自动补造内容或调用模型。
- 观察：隔离示例库中通过真实导入接口导入两条同岗位记录，再通过浏览器查看导入页与岗位详情，确认显示两条记录、一个待处理岗位，短描述显示重新采集提示且不再要求点击禁用按钮。浏览器没有执行上传文件步骤，也未覆盖已匹配／可匹配分类。
- 验证：前端类型检查与 283 项前端测试通过；真实 SQLite 接口重复导入测试通过。示例库基于现有演示数据并标记当前数据库版本，不能作为旧库迁移验证；未调用付费模型。
