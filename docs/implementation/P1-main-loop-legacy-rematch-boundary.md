# 主闭环 5C-3b：旧单岗位重新匹配边界

## 需求卡（2026-10-27）

- 用户目标：确认事实后使用同一份可恢复、可比较的分析；旧工作区仍可谨慎使用已有零模型功能。
- 发现：有保存分析引用的工作区虽隐藏旧按钮，但直接调用旧 API 仍能写入另一份匹配结果。旧路径的“零模型”只在计算前检查一次，随后使用带真实 Provider 能力的通用报告执行器；事实在两次读取之间变化时，不能保证仍为零调用。
- 本次：已关联保存分析的工作区在应用层拒绝旧命令，引导从关联分析更新；无关联的历史工作区保留原确定性功能，但运行时使用没有真实 Provider 能力的执行器。重复及冲突不能绕过边界。
- 不做：不改变历史报告、不删除旧工作区/事件、不修改模型授权通用实现、不把浏览器隐藏按钮当作服务端权限。旧单岗位多事务、更强的事实版本绑定及关联检查与执行之间的竞态属于遗留限制，后续需要单独处理；本切片不宣称它们已解决。
- 验收：真实 HTTP/SQLite 访问已关联工作区返回明确冲突、无报告/事件/调用；未关联历史工作区仍有规则路径；模拟预检后事实变化，最终执行不能触达 Provider 或写入报告；全量原测试与网页回归。
- OpenSpec 未安装，以此轻量需求卡执行。

> 后续状态：5C-3c 已停用旧写入接口，本文保留当时的设计和证据，不代表当前接口仍可运行。详见 [停用记录](P1-main-loop-legacy-write-retirement.md)。

## 实施与验证

- 已关联保存分析的工作区由服务端拒绝旧单岗位重算，返回 `application_rematch_use_scoped_update`；网页把错误解释为使用关联分析的更新入口。身份校验先于此检查。
- 未关联分析的历史工作区继续复用既有匹配报告算法，但该入口注入不持有模型客户端的匹配器；如果预检后事实变化、计算转而需要语义模型，会明确阻断，不能触发真实模型或伪报成功。
- 使用真实 HTTP 与隔离 SQLite 测试：已关联时返回 409，数据库完整转储不变，报告执行器未调用；未关联时规则匹配及相同命令重放成功，重放不新增写入。另以真实匹配工作流模拟预检与执行之间事实变化，验证阻断且无报告写入。
- 浏览器使用独立合成数据库打开已关联的工作区，点击“核对范围并更新分析”，实际进入原分析更新预检，页面显示岗位范围、复用数量及“当前仅预检，没有重算、保存新结果或调用模型”。这不是完整用户闭环验收。
- 旧接口的工作区关联检查与后续写入不在同一事务；旧报告和时间线也不是一个工作单元。关联状态并发改变仍可能绕过检查，遗留路径不能声称满足原子性或强并发隔离。下一切片应先决定安全停用旧写入还是统一事务，覆盖跨进程竞争与失败注入。
- 面试复现：预检后让资格条件变化并引入语义候选；与依赖一次检查不同，执行器本身缺少调用模型的能力，因此变化后得到明确阻断。这个边界不等于调用次数计量，也不等于旧路径已完整事务化。
- 本轮后端全量回归 1616 项通过（运行开始后补充的历史工作区测试不在此次全量收集内；最终相关测试单独 6 项通过）；网页测试 228 项通过，类型检查和生产构建通过。另对工作台及请求恢复相关测试 11 项通过。以上均使用隔离数据和禁用模型配置。
