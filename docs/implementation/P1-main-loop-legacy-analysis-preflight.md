# 历史工作区重新分析：统一规则预检

## 需求卡

- 问题：历史工作区没有保存分析，无法进入既有更新预检；事实变化后原匹配报告可能失效，直接重新匹配又可能触发未授权模型。
- 本切片先复用更新预检的同一判断，按历史工作区当前岗位给出报告可复用、规则重算、需要模型或输入阻断；查询只读，不能写报告、调用模型或制造历史分析。预检不是执行授权，也不是可恢复运行。
- 服务端严格区分没有保存分析的历史工作区，已关联分析继续使用原范围更新。契约由后端工作区接口与共享 Schema 持有。下一阶段将预检接到现有可恢复运行，不能使用旧的不可靠单岗位写接口。
- 验证：真实 HTTP、隔离 SQLite 比较数据库转储与禁用模型替身，覆盖可复用、规则重算、模型授权缺口及关联工作区拒绝；新契约与 Python 一致。
- OpenSpec 未安装，使用轻量需求卡。

> 后续进展：历史工作区已可从预检明确启动零模型分析；预检自身仍只读。见 [受控运行记录](P1-main-loop-legacy-analysis-run.md)。

## 实施与证据

- 新接口 `GET /api/v1/application-workspaces/{workspace_id}/analysis-plan` 仅供未关联保存分析的历史工作区使用；已有分析返回冲突，缺失工作区返回 404。返回当前事实版本、岗位分类、原因、建议修复入口与预检摘要，不假造原分析标识或保存结果。
- 使用同一个 `PlanAnalysisUpdateUseCase` 的事实判断与上限；读取历史工作区及事实使用 SQLite 读取快照，独立就绪检查可能观察到版本变化时按现有规则阻断。该查询是建议，不是执行许可。
- 隔离 SQLite 真实 HTTP 回归覆盖可复用、资料变化、需要模型、已有保存分析和缺失工作区；查询前后完整数据库转储一致，语义模型工作流替身未被调用。共享 Schema 与 Python 契约一致。相关后端测试 15 项通过，网页 232 项通过，类型检查和生产构建通过。
- 浏览器合成历史工作区实际显示“已有报告已变化，可由规则重算”，同时说明不会执行、保存或调用模型，以及受控执行入口尚未接通。只验证该界面，不声称用户已完成重新分析。
- 故障复现：资料更新后历史报告仍在，但旧工作区缺少可传给更新接口的保存分析标识。决策：复用同一预检而不是伪造历史结果，也不重启已退役的非原子写入口。面试说明：预检与执行必须分离；执行需要重新读取事实、原子提交和稳定重放。
- 下一步：把历史范围接入现有运行的步骤领取、固定版本、原子报告保存与恢复；未授权模型的情况必须保持等待。完整浏览器闭环及真实模型验收仍未完成。
