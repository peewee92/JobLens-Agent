# 主业务闭环 3C：保存可重开的分析材料

## 需求卡（2026-10-25）

- 用户：确认目标岗位后，需要刷新或重启后重开当时的差距与准备材料。
- 原行为：运行只保存差距指纹；跳转 `/gaps` 会按最新资料重算，且准备材料不属于本次运行。
- 目标：同一组已确认资料、意向、要求、匹配报告生成差距和逐岗位准备材料；有类型、带版本的结果与完成状态在同一事务保存；只读查询不重新执行。保存前再次检查事实，变化时保留历史产物并标记过期。
- 拆分：3C（本轮）事实绑定、结果保存/读取和结果界面；阶段 4 接入工作台及一键建立工作区；阶段 5 确认新事实与比较新旧结果。
- 不做：原生 LangGraph 中断迁移、自动投递、后台任务、模型调用、新算法、通用产物平台。
- 所有者：应用层负责业务组合；仓库负责同库原子保存；共享契约负责接口；网页只展示已保存结果。
- 失败边界：旧完成运行没有结果时明确缺失；结果/事件保存失败全部回滚；丢失租约不能提交；资料/意向/要求/匹配策略变化不得报告当前分析完成；不可用工作流不能包装成功。
- 验收：真实 SQLite 回滚/重启/版本变更测试；非空差距的不可变映射可序列化；保存结果 GET 零工作流/模型调用；网页实际完成确认和重开结果。
- 环境：OpenSpec 未安装、未初始化，使用本卡；所有既有未提交工作保留，所有数据库实验只在临时副本进行。

## 技术决策

保留运行记录作为权威状态，单独一列保存本次有类型的结果，事件只保存结果引用。复用既有确定性差距和准备工作流，但提供明确输入的入口，避免各自读取最新资料。SQLite 最终保存使用短写事务，在同一锁内核对事实并提交结果和状态；计算不持有数据库写事务。

## 已实现

- 迁移 `20261025_0025`：在权威运行记录增加 `analysis_result`，不另建产物系统，不双写旧库。控制状态只增加 `result_id` 引用；旧完成运行继续明确报告没有完整快照。
- `BuildSavedCareerAnalysisUseCase` 组合既有差距和准备算法。资料、意向、原报告、要求提取和匹配策略绑定到同一次分析；已释放事实在一个只读数据库快照中捕获，后续工作流不再各自读取最新资料。
- 最终短事务使用 SQLite `BEGIN IMMEDIATE`，先复核事实/释放状态，再按租约和修订号条件提交结果、状态与事件。变化时保存原事实产物并标记 `stale`；事件写入失败时结果和完成状态一起回滚。事务外确定性计算允许重算，不承诺恰好计算一次。
- `GET /api/v1/career-agent/runs/{thread_id}/result` 只读取已保存结果，另行派生当前适用性；不会触发材料生成、排序、模型或隐式继续。历史内容与当前适用性分开。
- `/agent/results/[threadId]` 展示原差距、简历事实要点、待核实项、面试证据提示及行动完成标准；精确链接到当时的匹配报告。原运行提供打开入口。旧指纹不会触发重算来冒充原材料。
- 共享 JSON Schema 和合成示例、Python/TypeScript 消费一致性已补齐。MCP 工具形状和普通受治理循环未增加新业务逻辑；本路径的确定性组合不虚增工具调用计数。

## 可复现失败

1. 非空差距的 `why_important` 是 `MappingProxyType`。旧 `dataclasses.asdict` 会因深拷贝报 `TypeError: cannot pickle 'mappingproxy' object`。专项测试先复现旧错误，再验证显式结构化序列化、指纹和类型化回读。
2. 测试 SQLite 触发器在完成事件插入时中止事务。API 返回 503，状态仍在 `skill_gap_ready` 且结果为空；移除触发器后显式继续，仅接受一次原人工决定并保存结果。
3. 真实工作流计算完成、提交前注入新的资料、意向、要求、报告或岗位元数据。五种情况均不报告完成；原事实版本的材料保存为历史，GET 明确返回不再适用。

## 面试口述
