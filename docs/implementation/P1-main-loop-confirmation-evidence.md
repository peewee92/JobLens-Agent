# 目标确认前核对本次排序依据

## 需求卡

- 用户：收到目标建议、需要决定是否确认的人。
- 原行为：确认页只列岗位，通用推荐页可能展示不同范围或较新的报告，不能证明本次排序使用了哪份依据。
- 目标：为每个排序岗位提供本次所用报告的链接，查看后可回到同一等待确认的运行。
- 不做：不重算排名、不自动确认、不把最新报告冒充原报告，也不把报告结论等同于面试能力评价。
- 契约：运行状态新增 `rankedReportRefs`；根据已保存的岗位与报告有序引用生成。长度不一致、标识重复或缺失时不生成引用。旧运行无引用时显示提示而不猜测。
- 失败边界：报告读取失败或报告已不存在时不自动换成最新版本；运行的继续和版本检查仍由后端负责。

## 技术决策与复现

直接使用运行中已保存的报告引用，而不是查询当前排序推测当时结果；旧运行缺少可信映射时明确提示。隔离数据复现：运行一批岗位，在确认前打开匹配依据，页面显示原报告及事实版本；返回后仍是同一等待确认的运行。

## 面试口述

“人工确认需要看到的是该次决策使用的证据，而不是当前另一次排序。我暴露已持久化的报告引用，无法建立可靠映射时宁可不显示，也不伪造历史依据。”
