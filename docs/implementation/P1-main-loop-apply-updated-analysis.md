# 主业务闭环：将更新后的分析用于工作区

## 需求卡

- 用户：确认新事实、查看新旧分析后，希望继续使用原求职工作区的人。
- 原问题：新分析的结果页只写“开始执行”，没有明确解释保存分析不会自动改变工作区，用户难以判断如何使用新结果或原有进度是否保留。
- 本次行为：更新分析结果显示“应用新分析到工作区”，解释显式关联、复用和保留历史的边界。已有执行记录只证明曾经应用，提示用户到工作区核对当前关联，不宣称当前引用一定未被其他分析改变。
- 不做：不自动关联，不修改业务接口、事务、记录或调用模型；首次分析沿用原入口。
- 失败边界：事实过期仍不能新建材料；原请求重试维持既有标识；已有工作区仍可查看。
- 契约归属：沿用已保存分析中的来源运行标识和已有执行接口，无接口变更。

## 核验与设计取舍

在隔离合成数据库中，通过浏览器把新分析应用于已有工作区：返回同一工作区，当前准备材料改为 v4；旧行动、已完成状态和原分析链接保留，新行动关联新分析。结果比较保持结论未变。新文案基于实际行为，不将“已保存分析”等同于“已应用到工作区”。

可复现原问题：在更新分析结果页看到“开始执行”，但无法从按钮判断它将复用原工作区及保留原进度。面试表达：长期求职工作区与单次分析分开；新结果由用户显式应用，已有人工进度和历史材料不被覆盖。
