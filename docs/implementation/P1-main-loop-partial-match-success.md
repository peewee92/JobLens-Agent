# 主业务闭环：批量匹配部分成功

## 需求卡

- 用户：一次处理多个岗位，其中部分成功，部分因输入或服务问题未完成。
- 原问题：失败不清除后端成功报告，但页面仅列出未完成项；只要有一个失败，就不提供本次成功范围的继续入口。超过 20 个成功岗位时，原跳转还会静默截断范围。
- 行为：页面列出本次已完成岗位，可逐项查看或仅带这批岗位进入分析；未完成项仍保留原因和修复入口。成功列表最多沿用批次上限 50，不再截断。全部成功且不超过旧页面 20 项范围时保留原跳转；超过 20 项时留在本页，使用完整范围进入分析。
- 不做：不自动重试、不把失败解释为不适合、不将本页临时列表冒充持久状态、不调用模型。
- 失败边界：进入分析后仍要重新检查报告适用性；刷新页面后可从岗位和已保存报告重新查找，本次临时列表不会保存。
- 契约：沿用批量匹配响应中的逐项状态和现有分析范围参数，不改后端接口。

## 设计与验证

成功与失败是同一批次的独立结果，失败不应阻塞用户使用已保存结果；显式范围避免把其他岗位悄悄加进分析。复现：批次中一个岗位成功、一个失败时，旧页面不跳转且只显示未完成项。组件渲染测试核对成功范围与 50 岗位边界，后端既有测试核对单岗位失败隔离。混合结果浏览器验证见下方补充；完整用户闭环仍未验收。

## 浏览器验证补充

在隔离 SQLite 副本中为两条合成岗位建立导入批次，使用离线替身匹配，并通过数据库触发器注入其中一个岗位的保存失败。浏览器实际点击匹配后，看到一项成功、一项失败及对应入口；点击“仅用已完成的岗位继续分析”后，分析页仅勾选成功岗位。复测还发现并移除了任务结束后“匹配 0 个岗位”的禁用按钮。该测试使用人工故障注入，不代表真实服务故障或真实模型质量验收。
