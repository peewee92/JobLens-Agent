# 岗位要求审核：可靠提示与候选选择

## 需求卡

- 用户与问题：匹配被审核基线阻断时，旧页面将“没有当前有效基线”描述为“从未建立”，并暗示重新分析能恢复；审核页还将离线重分析称为对齐目标版本，可能诱导覆盖当前样本。
- 目标：说明基线可能失效，提供人工审核入口；不承诺重分析能够解除阻断，也不再提供误导性的版本对齐按钮。审核页超过 20 个同版本候选时可选择 20 个，按后端的五个字段（含语义策略）分组，候选统计仅代表加载页。
- 不做：不改变发布授权、旧基线生命周期或业务数据，不替代服务端校验，不调用模型。超过首 100 条候选的其他版本仍不可在此页选择。
- 失败例证：隔离合成库的审核页有 69 条同版本候选，原先因要求数量恰好等于 20 而提示无法创建；缺少语义策略的前端分组也可能让后端拒绝混合版本。
- 技术决定：页面预选最多 20 条，服务端依然是创建与正式资格的最终检查者；历史审核不能因为界面调整被视为重新授权。

## 验证与限制

- 网页 291 项测试、类型检查和 `git diff --check` 通过。测试覆盖 21 条同版本候选和不同语义策略不能混选。
- 使用隔离合成数据库、禁用模型的本地服务，在浏览器观察到 69 条同版本候选且可一键选中 20 条；未提交审核批次或作人工判断。此验证不是正式质量验收，也未验证真实岗位。
- 匹配被阻断时的新版说明和链接由单元测试、代码检查覆盖；未对基线失效原因逐种进行浏览器验收。
- 面试口述：候选数量足够只是审核的必要条件，前端分组必须与后端相同；历史审核仍要按原有效期解释，不能靠界面重选绕过质量控制。
