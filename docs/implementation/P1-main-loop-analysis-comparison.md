# 主闭环 5C-2：保存结果之间的比较

## 需求卡（2026-10-27）

- 用户目标：确认新事实并更新分析后，知道同一岗位范围哪些结论变化、哪些未变，以及依据在哪里；不承诺排名上升。
- 原行为：两份结果能独立保存和打开，但没有比较入口；旧单岗位比较会自行寻找历史报告，不能作为本次更新来源的证据。
- 目标：沿新运行固定的原运行/结果引用，读取两次保存结果与明确绑定的历史报告。逐岗位展示推荐判断、证据覆盖、偏好判断、排序位置和目标选择变化。
- 比较边界：岗位要求或规则版本变化时不强行给改善/变差；历史报告缺失不读最新补齐；部分分析的未处理岗位明确列出；排序集合不同不比较名次升降。
- 事实边界：证据引用变更不等于能力增加；没有证据仍不等于不会；有新事实但结论不变也是合法结果。不增加模型调用、业务写入或第二套比较任务状态。
- 契约：应用层类型化投影 → Python 响应/共享 JSON Schema → TypeScript 页面。GET 只读，返回来源与版本以及稳定原因码；无保存历史则明确错误。
- 验收：实际更新到保存结果到浏览器比较；不变/改善/变差/混合/不可比；部分范围、归档报告缺失、绑定身份冲突、当前资料再次变化仍不污染历史对比；全库前后不变。
- 不做：本轮不统一工作台所有入口、不开发通用差异平台、不调用收费模型、不提交推送。OpenSpec 未安装，使用轻量需求卡。

## 已实现：5C-2（2026-10-27）

### 拆分与职责

1. 只读应用服务：校验本次更新固定的原结果引用、两份运行/结果/报告身份，按原确认目标或原请求批次投影比较。不自行猜测上一份报告，不读取最新资料、岗位要求或匹配报告。
2. 数据读取：同一个 SQLite 读事务查询两份保存结果和它们明确绑定的归档报告。没有新表、写入、迁移或比较任务状态；缺失报告只返回诊断。
3. 契约与页面：`GET /api/v1/career-agent/runs/{threadId}/comparison`，共享 `analysis-comparison.schema.json`，Python 与 TypeScript 消费。保存结果响应增加可空来源运行/结果引用，从保存结果页进入比较。
4. 用户解释：推荐、证据覆盖、偏好判断、来源版本、逐项证据与个人事实引用、确认目标增减；只有同一完整可比范围才显示排序位置变化。旧结果、本次结果及明确报告均可打开。

### 技术决策

- **比较是保存事实的只读投影，不是另一条重新匹配工作流。** 不复用旧单岗位模块中“查找前驱”的逻辑，避免把后来生成的报告冒充当时来源；复用现有存档报告结构和查询仓库。
- Profile 的不同版本本来可能是不同数据库行，不能要求新旧 Profile ID 相同。分别核对各自版本与对应报告身份，再沿显式来源关系比较。
- 推荐/证据判断的改善、变弱或混合不等于能力变化或录用概率；引用 ID 改变本身不算改善。方法/提示词/模型不同显示警示，不把变化完全归因于新事实。
- 岗位要求、策略版本或同标识要求内容不一致时，只展示两侧归档推荐与不可比原因；不计算改善。目标集合变化不比较汇总差距数；部分结果和报告缺失不计算名次升降。
- 归档报告缺失时保留原引用并明确缺失；身份或范围损坏时返回结构化 409。数据库暂不可读返回安全 503，不暴露 SQL、异常消息或个人资料。

- 后端全量 **1608 项通过**（176.14 秒）；新增比较测试 **13 项通过**，包含真实 HTTP/SQLite 的新旧保存结果、后续资料更新不污染比较、部分范围、明确报告删除后不找最新补齐、安全错误和共享契约。改善/变弱/混合/策略不同/要求内容不同使用明确标注的合成快照变体，不冒充真实模型质量测试。
- 网页全量 **219 项通过**；最终样式改动后定向渲染 2 项再次通过；TypeScript 检查、最终生产构建通过。
- 浏览器使用此前通过实际更新/确认流程生成的合成库副本：从 v2 保存页点击比较，显示原 v1 → 新 v2 的 8 岗位“结论未变”；展开查看两侧理由、证据与个人事实引用。库内当前事实已是 v3，比较仍正确使用历史 v1/v2。
- 浏览器另开 v3 的部分分析比较：5 个已完成岗位结论未变，另外 3 个明确未分析，不当成淘汰或名次下降。刷新最终构建后内容保留。点击原报告依据进入明确 `reportId` 的历史详情，显示资料第 1 版，而不是最新报告。
- 浏览器直接打开没有更新来源的原分析比较地址，显示“这不是带有原结果引用的更新分析”，并能返回结果；没有任意选择历史报告来拼凑比较。

- 日志指针：`/tmp/joblens-analysis-comparison-current-path`，其中 `backend-full.log`、`target.log`、`web-full.log`、`build-final.log`、`browser-evidence.json` 和两份比较 JSON。截图：`/tmp/joblens-analysis-comparison-unchanged.png`（首次构建）、`/tmp/joblens-analysis-comparison-partial.png`（最终构建）。临时目录不作为开源仓库长期证据，稳定复现入口是测试和上述操作步骤。

### 可复现失败

`test_missing_bound_report_never_falls_back_to_latest`：在一次真实保存的更新后，仅删除合成库中原分析明确引用的一份报告。本次报告仍存在，但比较必须保留旧引用、返回 `historical_report_missing`，取消名次升降；不能拿新版报告替代历史。另有身份/来源/排序/范围损坏检查与数据库错误脱敏测试。

### 面试口述

“新增事实不代表能力变强，也不保证排名上升。我把每次分析固定的报告当作历史依据，比较接口只读两次明确保存的版本。引用换了但证据覆盖没变，就告诉用户结论未变；要求或规则变了，就停止给升降结论。部分岗位未完成也不会当作淘汰。它不需要额外模型或状态机，且整个浏览器查询过程数据库不变。”
