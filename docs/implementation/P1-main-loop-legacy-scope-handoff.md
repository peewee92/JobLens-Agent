# 主闭环 5C-3d：历史工作区保留岗位范围

## 需求卡

- 历史工作区确认事实后，没有保存分析可供范围更新；通用入口默认选最近五个岗位，可能不包含用户刚才的岗位，且只读已有匹配报告。
- 本切片：跳转时携带岗位标识，加载并仅预选该岗位，即使不在最近 20 条；说明需要先核对现有报告与资料版本，提供返回岗位检查入口。禁止自动执行、模型调用或伪造更新结果。
- 无效岗位不能被静默替换成其他岗位；恢复未完成请求仍遵循原请求，不被新范围覆盖。历史数据不迁移、不承诺单岗位重新匹配已完成。
- 验收：选择范围的纯逻辑测试、网页类型与构建、浏览器检查超出最近列表的岗位及返回路径。OpenSpec 未安装，以需求卡记录。

> 后续进展：历史岗位现可从工作区预检启动规则分析，见 [受控运行记录](P1-main-loop-legacy-analysis-run.md)。

## 本轮结果与限制

- 历史工作区的主按钮和事实确认提示都携带原岗位标识；分析页只预选这个岗位，缺失时清空选择并说明原因。若最近列表不包含它，会单独按标识读取该岗位；不会因此自动启动运行。
- 浏览器在隔离合成数据中从工作区跳转，确认仅原岗位被选中、显示报告版本提示和岗位详情入口；不存在的岗位显示错误且运行按钮不可用。本次合成岗位恰好在最近 20 条内，超过 20 条的真实浏览器路径尚未实测，不能把代码分支当成浏览器验收。
- 后端相关回归 13 项通过，网页 232 项通过，类型检查及生产构建通过。未触发模型或真实数据库写入。
- 复现和取舍：此前跳转默认选最近五个岗位，与刚确认事实的岗位可能完全不同；现在显式携带范围，找不到时不回退。面试时可说明：用户意图是确定性输入，不能由默认列表替代；已有待恢复请求仍以原命令为准。
- 仍待补齐：此入口只读历史报告；旧报告不兼容时，如何在没有保存分析的工作区使用可靠、有预算控制的规则重算并产生新分析，尚未解决；旧单岗位页面可能触发模型，不能把它当作零模型受控更新入口。正常、证据不足和故障恢复三条完整用户路径也尚未验收。
