# 已有经历但没有技能条目时的匹配

- 用户与问题：用户确认了有来源的真实经历，却尚未整理技能；现有发布检查及编辑器要求至少一项技能，导致无法分析岗位，与“经历或技能证据即可开始”的产品规则不符。
- 目标：允许只凭已确认经历开始匹配；若无可用技能支持，保留待核实或证据不足，不推断用户会或不会。已填技能仍须关联有效证据。
- 不做：不生成技能、不更改匹配策略、不重算历史报告、不放开缺少经历或资料未确认的前置条件。
- 契约：保持已有接口和旧原因码兼容；取消当前版本对空技能列表的阻断。资料编辑器允许移除最后一个技能。
- 验证：真实接口与隔离 SQLite 构造缺少技能但有经历的用户，生成真实证据不足报告，确认新事实后重算并核对旧报告；验证无证据及无效技能关联仍被阻断。浏览器界面单独验证。

## 实施与本轮证据

- 后端取消空技能列表这一独立阻断，保留经历必需及已填写技能的证据关联校验。旧原因码继续保留以兼容既有消费者。
- 编辑器允许移除最后一项技能，并解释技能可暂不填写。
- 隔离 SQLite 的真实接口测试：确认只有不相关经历且技能为空的资料后，真实匹配工作流生成 `conditional / low` 报告，要求标为 `not_matched` 且没有证据引用，预检不将其包装为目标建议；确认另一份含 Python 证据的新资料后重新匹配，生成有证据引用的新报告，旧报告保留并标记过期，随后可确认目标并保存分析。该结果只说明合成样例，不承诺补充事实后一定改善。
- 本轮修复前可复现的失败：相同无技能资料调用匹配接口返回 409 `eligibility_inputs_not_ready`；修复后上述路径通过。针对相关后端用例 21 项通过，前端类型检查和 271 项测试通过。
- 浏览器使用独立合成数据库，实际删除最后一项技能并确认保存；页面显示 0 项技能和“可用于后续岗位匹配”。未验证真实用户或真实新岗位。
- 面试口述：经历证据是匹配入口；技能条目是用户确认的结构化事实而非准入门槛。缺失的技能不等于能力不存在，已有技能仍必须有证据。结果版本化，资料变化时旧报告保留但标记过期。
- 后端完整测试套件：1659 项通过（使用本地虚拟环境）；`git diff --check` 通过。
