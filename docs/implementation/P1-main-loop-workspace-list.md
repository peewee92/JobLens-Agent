# 求职工作区历史入口

## 需求卡

- 用户：在多个批次积累超过 5 个目标岗位后，希望找回先前的工作区及行动进度。
- 原问题：工作台只显示最近 5 个工作区，没有全部列表；更早的工作区只能依赖旧地址或逐个寻找，长期求职记录容易被忽略。
- 本次：工作台保留最近 5 个摘要，并提供只读的全部工作区分页；每页最多 20 个，只返回本地用户的工作区及未完成行动数，允许进入原工作区。
- 不做：不创建工作区、不触发分析、不自动更新行动或投递状态、不新增进度副本。排序按最近变更，翻页期间若记录变更，顺序可能变化。
- 契约：`workbench-workspace-page.schema.json`；读取失败明确提示重试，不把失败当成空列表。
- 验证：隔离 SQLite 接口测试覆盖 22 个记录、两页完整性、用户隔离、参数边界和共享结构一致；隔离浏览器从首页打开列表并看到已有工作区。另在独立合成数据库副本中构造 27 个工作区，浏览器验证第一页 20 项、第二页 7 项，进入第二页的旧工作区后返回，再点击上一页。该验证不覆盖翻页期间并发改动。

## 技术决策与面试口述

工作台摘要继续有界，历史列表使用独立只读查询，避免把长期求职行动塞进 Agent 运行状态。复现方式：创建超过 5 个工作区，首页只能看到最近 5 个；现在可通过“查看全部求职工作区”找回历史。分页基于偏移量而非稳定快照，因此页面明确告知并发更新可能导致顺序变化。
