# 恢复目标确认时显示岗位名称

## 需求卡

- 用户问题：恢复等待确认的分析时，目标岗位可能不在页面当前加载的前 20 条里。即使页面已通过运行范围的名称接口取回岗位名称，确认选择框仍只读取当前页，因而显示内部岗位编号。
- 本次行为：优先显示当前页岗位名称及公司；当前页缺少该岗位时，使用运行范围名称接口返回的名称；名称不可用时保留岗位编号，不猜测或使用别的岗位。
- 边界：不改变排序、岗位范围、确认命令或报告引用；不调用模型。岗位名称是当前读取的显示名称，不声称是运行时的历史快照。
- 验证：组件测试覆盖当前页、回读名称和缺失名称的三种显示；网页类型检查和全部 288 项测试通过。隔离数据库副本中构造等待确认夹具，使目标岗位不在首屏，在浏览器中恢复后看到 `Synthetic Large 40`，取消勾选后确认按钮禁用。夹具仅用于显示测试，报告引用未重新构造，因此没有提交确认，也不代表验证了完整分析流程。
- 失败复现：旧代码在该夹具下忽略已加载的运行范围名称而显示 `job_large_40`；修复后使用已有名称映射，不新建业务状态。
- 面试口述：分页是浏览优化，不能决定历史运行里哪些岗位有可读名称；恢复时以已保存的岗位标识查名称，查询失败明确退回标识，而不改动用户的目标集合。
