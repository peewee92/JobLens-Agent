# 主分析入口：加载更多岗位

## 需求卡

- 用户问题：岗位超过 20 个时，分析页面此前只列出第一页，却声称可以选择最多 50 个，较早岗位无法在此选择。
- 本次行为：按需通过同源只读接口每次加载 20 个岗位，保留已选择项与原工作区指定岗位；最多选择 50 个，到上限时其他选择项禁用。加载失败保留现有选择并允许重试。
- 不做：不自动匹配、不调用模型、不创建分析；不会假称所有岗位已有可用匹配报告。此切片不替代旧批量运行的服务端恢复。
- 技术决策：分页偏移依据后端返回页长度而非合并后的列表长度，避免置顶的指定岗位造成跳项；重复岗位按标识去重。岗位在分页期间被导入或更新可能改变偏移排序，这不是快照分页；用户应核对范围。
- 失败例证：服务端返回的偏移不匹配或报告尚有岗位却返回空页时，页面显示重试信息，不静默推进。
- 面试表达：读取型分页和已选业务范围分开管理；固定用户显式选中的岗位身份，不让“加载更多”改变选择或触发分析。

## 验证

- 前端 239 项测试、类型检查通过，新增测试覆盖置顶岗位、重复项和错误页；生产构建通过（最后仅补充了达到 50 个后的禁用条件）。
- 浏览器连接隔离合成数据库，首屏 20 个岗位，点击加载更多后出现第二页；勾选第二页一项后数量从 5 变为 6，先前选择保持。未运行模型或触碰真实数据库；未验证动态插入岗位时的快照一致性。
