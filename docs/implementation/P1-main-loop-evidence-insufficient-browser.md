# 证据不足到再次分析：隔离浏览器验收

## 目的与边界

验证从真实匹配工作流产生的“证据不足”结果出发，用户能否通过页面核实要求、确认事实、重新匹配、确认目标并继续求职行动；不要求结果必然改善。此记录不代表真实岗位或模型质量验收。

## 环境和准备

- 2026-10-28，本地单进程后端、前端和临时 SQLite 数据库；使用 `scripts/seed_mcp_demo.py` 创建全合成资料、岗位和已审核要求。脚本使用 ORM 创建当前结构；仅对此一次性数据库执行 `alembic stamp head`，不是迁移验收。
- 通过本地接口将合成资料改为仅有无关经历、无技能，再调用真实匹配接口生成 `low` 报告，返回 `providerCalls=0`。初始资料及报告为隔离准备，不是浏览器步骤；初始种子还包含其他预生成报告。
- 后端使用离线 `fixture`，未授权真实模型；以下页面操作只作用于此合成库。

## 浏览器实测

1. 选定合成岗位检查后，页面说明证据不足、没有目标建议，运行按钮禁用；进入岗位详情可见具体要求、未检索到证据的原因，以及“没有证据不等于不会”。
2. 从岗位详情进入资料页，新增合成 Python 项目经历、来源及关联技能，人工审核并保存；返回岗位后，原报告清楚标记为历史，当前资格判断与历史结论分别展示。
3. 用户点击重新生成匹配报告。页面显示新旧版本及“证据未覆盖 → 已有支持”，同时保留并能打开旧报告；该样例的改善不代表其他数据一定改善。
4. 返回原岗位范围并重新检查，启动分析、刷新等待确认页，已保存的目标确认状态恢复；确认后打开保存的资料 v3 分析与准备材料。
5. 创建工作区、开始并完成一项行动。完成后事实计数仍为零；填写合成成果后先提交为待确认提案，再单独确认，资料更新为 v4，旧分析被标记过期。
6. 从工作区预检原目标并发起规则更新，无模型调用；人工确认目标后保存 v4 分析。对照页面显示推荐和覆盖判断未变、证据引用发生变化，并保留 v3 原始结果链接。
7. 将新分析显式应用到已有工作区：复用同一工作区，当前材料引用 v4，旧行动与已确认提案仍在；新分析生成新的行动，旧行动位于历史区域，不声称自动合并。

## 待验证

- 该路径从预先准备的已审核岗位与真实生成的低证据报告开始，未覆盖真实采集、要求提取或用户自行创建首份资料。
- 此次刷新验证的是等待确认页面；中途进程重启、保存失败、网络丢响应与并发冲突需要各自的浏览器或真实 SQLite 故障证据，不能由此推断全部通过。
- 本轮未调用收费模型，未修改真实求职记录，未提交或推送。真实新岗位须单独授权后验收。

## 技术决策、失败与面试口述

- 决策：低证据不等于硬冲突，也不伪造目标；用户确认事实后显式重算，保存的旧报告和材料仍可追溯。
- 可复现的环境失败：仅由种子脚本创建的测试数据库没有迁移版本标记，工作台显示环境未就绪；为该临时数据库标记版本后恢复。不能把标记版本当作旧数据库迁移验证。
- 面试口述：“我用隔离数据库从真实规则报告走到事实确认、重算和工作区复用；变化未必是排名提升，历史材料和行动进度必须保留。真实模型质量与故障恢复分开验收。”
