# P1 · 首次使用完整流程

依据 [首轮体验与已修复部分](../../UX_AUDIT.md) 和 [分析失败恢复](P1-first-run-recovery.md)。使用已有本地 SQLite、确认权限和运行恢复；不调用收费模型、不部署、不推送、不编造经历或岗位结论。

| 切片 | 验收条件 |
| --- | --- |
| 1. 首页与简历 | 冷启动有「确认资料 → 添加岗位 → 比较并准备」进度及主要下一步。PDF 入口在资料页首屏；成功/失败在操作旁可见。一次核对能更正年限、填写最少偏好，再确认保存；部分保存只重试缺少的部分。已确认资料不能被自动覆盖。 |
| 2. 批量、补写与单岗 | 不靠插件即可粘贴多条或逐条加入；提交前核对，逐条反馈，重复复用而非新增，描述不足存为待补；经确认补写原手工岗位并保留历史原文及来源，同一岗位原报告不当成当前。岗位原文、分析、核对和匹配在同一处顺序展示；不能跳过确认、费用授权或未知结果保护。 |
| 3. 比较、诊断与准备 | 比较保留原选择、显示实际参与与原因，成功后能直接找差距、简历与面试；加分项不冒充门槛；说明用真实标题与业务词，内部编号折叠。主路径提交有就近等候、禁重和可处理的错误提示；页面转场有加载反馈。 |
| 4. 复测交付 | 新空库、新浏览器，只用合成素材，截图后用鼠标和键盘操作。覆盖空资料匹配、PDF、三类岗位、重复及乱码、补写、已知/未知错误、正式比较、准备、行动刷新。问题继续修复并提交；验证后切换可访问的本地版本。 |

输入/输出以现有资料、岗位事实、分析报告和运行状态为准；任何新公开字段由后端及共享契约定义。既有历史不改写，未参与不等于能力不足。
