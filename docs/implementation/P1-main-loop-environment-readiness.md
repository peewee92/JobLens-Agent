# 主业务闭环：阶段 1 运行环境就绪

## 需求卡

- 目标：用户在进入分析或求职工作区前，能看到数据库不可用、迁移落后或缺表的明确说明，而不是健康检查成功后遇到不明 500。
- 范围：新增只读就绪接口、首页 / Agent / 工作区入口提示、迁移副本验证。
- 不做：不升级真实数据库，不调用模型，不在启动或 GET 请求中自动迁移，不提前修改匹配策略。
- 契约：`packages/contracts/schemas/system-readiness.schema.json`；后端负责检测，网页负责中文解释。
- 完成标准：旧版本、空库、缺表、连接失败返回 503；最新完整数据库返回 200；存活检查保持兼容；检测不创建不存在的 SQLite 文件；数据库副本升级后原有数据保持不变。

## 技术决策

存活与就绪分开。`/api/v1/health` 只证明进程存活；`/api/v1/readiness` 同时检查连接、Alembic 版本和 ORM 所需表。没有启动自动迁移，避免对错误数据库产生不可逆修改。

## 可复现失败

用临时数据库执行 `alembic upgrade 20260810_0017`，启动服务。存活接口应为 200，就绪接口应为 503 / `migration_required`，网页应提示备份并检查迁移，而不是继续发出工作区查询。

## 面试口述

“进程活着不代表业务能用。我们曾遇到旧数据库缺少求职工作区表，但健康检查仍成功，因此增加不自动修库的就绪检查，把环境故障和业务输入不足分开。”
