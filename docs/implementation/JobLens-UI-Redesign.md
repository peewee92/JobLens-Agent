# JobLens 前端重构：需求卡与验收

- 用户：初次使用的个人求职者，以及要恢复已有分析的用户。
- 现状：空库首页同时展示多个空面板；资料页有两个相似手填入口。基于 PR #13 修复后的版本观察。
- 目标：资料录入、岗位核对、比较准备三个切片，各自通过本地构建、自动回归和 Computer Use 复验。
- 边界：FastAPI 与共享契约是业务事实来源；不改 API、SQLite、历史报告、证据门禁或模型授权。不接新服务、不自动投递。
- 技术决策：只把项目需要的 shadcn/ui 模式纳入本地组件，不换数据层、不引入 Tailwind Preflight；原生表单保留，只有复杂焦点行为使用 Radix。
- 样式：共享蓝色品牌、浅色背景和系统字体；间距 4/8/12/16/24/32/48；主要触控高度 44px。新组件按语义提供按钮、状态与可恢复反馈。
- 可复现反例：新空库打开首页、进背景页，可见分析、动态等空面板和两个手填按钮；改后分别只有当前动作和一个明显的快速入口。
- 面试口述：把「视觉更新」拆成可复现任务，先保住确认和证据，再用新空库、多尺寸浏览器回归验证没有把用户困在失败页面。

## 来源

Button 的变体 + Slot 模式和 Dialog 的 Portal/Trigger/Content 模式根据 [shadcn/ui v4 文档](https://ui.shadcn.com/docs/tailwind-v4)及 [Radix Dialog 文档](https://www.radix-ui.com/primitives/docs/components/dialog)实现；仅适配这些模式，不使用产品模板。Tailwind v4、Radix 与相关依赖的实际版本锁定于工作区锁文件。shadcn/ui 衍生组件的许可记录在组件目录。

## 如何继续维护

- 先确认一个页面的主要行动，然后才选按钮变体。成功、待补、不能继续和历史状态用明确文字与颜色双重区分。
- 表单错误要说明哪些内容保留；旧报告和原岗位要求仍从原链接打开，不用最新事实填补历史。遇到新旧格式冲突，以可见选项消除歧义，不静默吸收文字。
- 空状态至少区分未添加、筛选无结果、资料未确认和结果已过期；不要用一个通用「暂无数据」替代。
- 新功能优先测试离线与失败路径。验收时使用空库做首次体验、独立合成历史做恢复；确认提交版本再拍图。没有真实模型回归就明确记录，不扩大模型授权。
- 交互可继续简化为「核对资料 → 一次粘贴 → 从同批核对后比较」。后续可把岗位缺失原因及返回同批入口集中到比较页，不去掉人工核对，也不替用户填未知职业事实。

操作记录、修复编号及截图索引见仓库根目录 `UX_AUDIT.md`。
