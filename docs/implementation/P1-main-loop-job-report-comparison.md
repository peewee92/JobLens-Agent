# 岗位报告的新旧核对

- 用户：证据不足、没有可确认目标的人，在补充真实资料后更新单个岗位匹配。
- 问题：旧报告虽能打开，但页面未在同一处说明该岗位的新旧要求判断，用户只能来回记忆；这类用户尚无保存的 Agent 分析结果，不能使用运行结果对比页。
- 本次：仅比较同一岗位的相邻两份已保存报告，展示版本、结论、逐条要求判断及已保存原因；岗位要求版本或策略不一致、缺失版本信息时明确提示不可直接比较，不推测变化原因。不同求职意向、模型或提示词也须明确提示。仅展示，不新建状态或触发模型。
- 验证：组件测试覆盖新旧变化、不变及版本不兼容；浏览器用隔离数据查看真实生成的两份报告。

## 本轮验证与边界

- 在隔离数据库中使用真实接口和规则匹配，先保存只有无关经历的资料及 `low` 报告，再确认 Python 事实并生成 `strong` 报告；两次返回的模型调用数均为 0。浏览器查看到两份相邻报告的版本、要求判断、证据数量和各自原始原因；也重新打开了旧的证据不足报告。
- 前端类型检查通过；完整前端测试 278 项通过，随后展示基础条件的小调整又通过类型检查与 7 项针对性测试。`git diff --check` 通过。
- 可复现的限制：如果两份报告的岗位要求版本或规则不同（包括旧记录无策略版本），页面明确不作逐项直接比较；如果没有保存要求明细，也不会说结论未变化。
- 技术决策：仅对照已有快照，不生成另一份对比记录，不把版本变化当作因果证明。方法或偏好版本不同会提示；相同版本仍不排除岗位条件等其他输入变化。
- 面试口述：没有目标建议的用户也能看到单岗位更新前后记录；系统显示原始依据和版本，而非要求模型编一个“变好原因”。
- 仍未完成：尚未用真实新岗位或完整浏览器路径验收，也未验证所有用户主流程和故障恢复。
