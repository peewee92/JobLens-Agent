# 主闭环 5C-3c：停用旧单岗位写入，保留历史

## 需求卡（2026-10-27）

- 用户：已有或历史求职工作区用户。确认新事实后，需要可追溯、可恢复的分析，而非绕开新运行产生另一份结果。
- 现状：旧接口分别提交报告和事件；关联检查与写入不原子。即使检查时未关联，并发更新工作区也能在检查后发生。历史报告重放也不是固定结果。
- 决策：保留接口兼容明确拒绝（410），所有工作区都不能通过该入口写入；历史报告、事件、行动和事实不删除。已有分析走限定范围更新，无保存分析的历史工作区引导用户重新选择岗位创建分析。新运行不会自动合并旧行动或承诺比较历史结果。
- 不做：不重建旧接口事务和锁，不将未知模型调用静默重试，不迁移历史数据；不声称历史工作区已经具有保存分析或完整关联。
- 契约所有者：FastAPI 旧路由及其网页提示；拒绝响应 `application_rematch_retired`，网页入口与概览要给出明确下一步。
- 验收：真实 SQLite 上已关联、未关联和重复/并发旧请求均返回拒绝且无业务写入；网页无旧写入按钮，历史工作区有重新分析入口，关联工作区仍保留范围更新入口；测试不能只检查字符串。
- OpenSpec 未安装，使用此需求卡。

## 实施与验证

- 接口统一返回 `410 application_rematch_retired`，不再读取工作区后决定能否写入；因此关联状态如何并发变化都不能让此 HTTP 入口写入。原实现源码保留用于历史参考，已移除对外依赖装配；这不意味着旧实现自身已事务化。
- 隔离 SQLite 的真实 HTTP 测试覆盖关联和未关联工作区，每种均同时发送相同及不同标识的三个请求；全部拒绝，完整数据库转储不变，报告执行器未调用。相关后端回归 13 项通过。
- 浏览器发现确认新事实后，旧简历和面试接口的 `application_workspace_facts_stale` 导致整个工作区失败；现在仅对该明确错误局部展示阻断，其他错误仍向上传播。实际浏览器复验显示已确认事实、原行动、投递状态和历史事件仍可见，首要按钮进入岗位选择页；旧重算按钮不再出现。
- 当前新分析页面只读取已有匹配报告，且岗位列表有数量限制；历史工作区没有保存分析时，用户还需选择岗位并解决不兼容的匹配报告。这一替代入口不等于历史数据自动迁移，也未证明完整重新分析链路。
- 技术取舍：停用非原子的旧写路径，比给两套编排分别补锁更简单；历史数据保留，而可恢复更新只由新版运行承接。故障复现：确认事实后旧准备接口返回 409，之前整个页面显示服务错误，现在仅阻断新材料。面试说明：显式退役不可靠写路径并保留只读历史，不把 UI 隐藏按钮当成并发控制。
- 网页 231 项测试通过，类型检查和生产构建通过；页面验证使用隔离合成 SQLite，未调用模型或修改真实求职记录。
- 后端全量回归 1617 项通过；该运行启动后调整了“下一步”优先级并新增一项测试，最终版本另跑上述 13 项关联回归验证。全量通过不能替代三条完整浏览器业务路径。
