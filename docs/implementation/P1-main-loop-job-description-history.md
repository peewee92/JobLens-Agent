# 岗位历史采集描述的只读核对

- 用户问题：重复采集后的当前描述可能较短；已有导入快照不能通过界面核对。
- 本轮：岗位详情可展开最近 10 条导入时保存的描述，标注导入记录保存时间和输入序号；同时展示当前描述。不自动恢复、合并、选择版本或重新分析。
- 契约：`GET /api/v1/jobs/{job_id}/description-observations` 只返回该岗位的描述、导入标识、序号和保存时间，不公开采集快照的其他字段。每条最多返回 50000 字符并标明截断；还有更多记录时明确提示。共享契约为 `packages/contracts/schemas/job-description-observations.schema.json`。
- 边界：没有快照或描述字段的旧记录显示无法还原；没有导入记录不代表岗位没有历史；读失败不影响当前岗位查看且不冒充无历史。保存时间不是招聘网站发布时间，也不能证明岗位仍有效。只有本地单用户访问边界，不新增身份认证或公开部署能力。
- 失败例证：同一岗位完整描述之后导入短描述，旧实现只能看到当前短描述，虽然内部审计保存了先前原文也无法核对。
- 技术决策：先提供有界、字段白名单的只读视图，避免以长度自动替换用户当前事实；历史恢复需要后续单独设计并发检查、来源和分析过期规则。
- 面试口述：历史观察与当前岗位是两种事实；读取历史只做透明展示，不把无法证明的旧版本自动当成当前真实岗位。

## 验证与限制

- SQLite 接口测试覆盖同批不同描述、原始额外字段不泄露、旧快照缺失、数量与文本长度上限，以及不存在岗位；响应按共享 JSON Schema 校验。
- 浏览器使用隔离数据库展开同一合成岗位的两次描述，实际看到当前短描述及保存的旧完整描述。前端测试覆盖无历史和读取失败的区别；未验证实际招聘网站、用户真实数据、恢复历史或完整求职闭环。
