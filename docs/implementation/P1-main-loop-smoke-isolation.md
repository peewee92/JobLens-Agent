# 主流程冒烟的本地隔离

- 用户与问题：开发者执行主流程或审核冒烟时，本地环境可能配置真实模型与现有运行检查点；旧脚本继承部分配置，并使用固定端口，可能连接或干扰其他本地服务。
- 目标：两个冒烟脚本显式使用临时数据库与临时检查点，必要提取使用离线替身，其他模型和要求提取备用提供方禁用；使用临时端口并检查子进程退出。保留原来的业务断言，不将冒烟称为完整浏览器闭环。
- 不做：不修改应用的用户配置、不清理真实数据库、不调用收费模型。端口选择和启动之间仍有竞争窗口；随机端口与退出检查降低风险，但不构成端口所有权证明。
- 验证：两条脚本分别从空临时库执行真实迁移，均通过。再次将外部环境中的语义匹配、意图和备用提供方设为 `openai`、模型地址设为不可达本地端口，两条脚本仍通过；仅证明这些执行路径在该环境下没有依赖这些提供方，不证明全产品不存在其他模型调用。
- 失败例证：若本地固定端口已有服务，原脚本只检查端口上的 HTTP 响应，不能保证响应来自本次启动的子进程。
- 技术决策：测试自己的资源应显式指定，而不是依赖开发者 `.env`；临时资源和模型边界与被测业务状态分开。
- 面试口述：我将冒烟的数据库、检查点和提供方固定在隔离环境，并保留真实迁移和接口；同时说明随机端口仍有竞争窗口，不把这种测试冒充完整端到端验收。
