# 旧匹配入口的零预算保护

## 需求卡

- 用户与问题：用户在岗位详情或批量匹配入口操作时，旧环境可能已配置真实语义模型；旧接口没有逐次授权和费用记录，不能因为点击按钮就触发付费请求。
- 实现：HTTP 依赖构造语义匹配器时，对配置为 OpenAI 兼容提供方的情况返回阻断适配器，不构造真实模型适配器；规则不需要模型时仍可继续，离线替身不受影响。需要真实语义调用时返回明确原因码，页面显示无授权与费用记录的说明。
- 不做：不提供绕开限制的全局开关；不虚称已经实现逐次授权、真实调用计数或预算账本；不改变离线评测脚本的适配器工厂。
- 边界：这是语义匹配的 HTTP 保护，不覆盖岗位要求提取、简历提取、自然语言或独立评测脚本；这些入口仍需分别检查并补齐逐次授权、调用计数与未知结果处理。
- 验证：配置真实提供方时测试替身工厂没有被调用，运行时返回明确阻断；离线替身仍可构造；错误接口返回结构化原因。没有进行真实模型调用。

## 决策与失败例证

旧入口的历史配置可指定真实提供方，但请求缺少单次预算和授权，直接放行可能带来用户未知的费用。本阶段在 HTTP 依赖边界拒绝构造在线语义适配器，而不是依赖页面上的说明或静默切换模型。用户仍可查已有结果；需要在线语义的操作明确受阻。面试说明：前端提醒不是安全边界，服务端必须在实际模型调用前执行不可绕过的预算检查；本次是临时零预算边界，完整按次授权与实际用量账本仍未交付。

## 扩展切片：资料与岗位要求提取

- HTTP 依赖对资料提取、岗位要求提取同样拒绝构造真实适配器；岗位要求的主提供方或备用提供方任一配置为真实提供方均受阻，避免备用路径绕过边界或静默切换。配置备用真实提供方时，即便主提供方是离线替身也需移除该备用配置后才能执行离线提取。
- 单岗位接口使用独立的授权缺失原因码。批量执行会记录此原因、停止后续岗位，并向页面解释是未授权，而不是将其误称为提供方故障或触发 30 分钟故障冷却。确认范围的复选框不再声称允许真实费用。
- 回归：后端 64 项、网页 236 项及网页类型检查通过；无真实模型调用。网页实际浏览器交互、逐次授权账本以及独立评测脚本仍未验证或实现。本次保护只覆盖使用这些 HTTP 依赖的入口，不声称覆盖所有可能的模型调用路径。
- 决策：检测备用真实模型并整体拒绝比悄悄剔除备用配置更透明；失败例证为“主提供方为离线替身、备用提供方为真实模型”，依赖构建阶段即阻断并且真实工厂未调用。

## HTTP 与浏览器补充验证

- 使用真实资料提取工作流与隔离 SQLite 的 HTTP 测试：模拟配置真实提供方，发送资料提取请求，接口返回 `profile_model_authorization_required`，真实工厂未调用，未产生职业资料记录。
- 使用隔离合成数据库和本地浏览器，将岗位要求提供方配置为 OpenAI 兼容方式（测试用无效凭据）；用户勾选离线范围并点击重新分析后，页面显示未接入逐次授权及费用记录的原因，后端返回 409，原已保存要求仍可查看。工厂阻断由自动测试独立验证；该测试不访问真实模型。
- 局限：该浏览器检查覆盖单岗位入口；批量入口的授权缺失分支、真实 HTTP 费用账本以及授权后单次调用尚未完成浏览器验收。

## 批量匹配错误归因

- 已发现旧批量匹配把授权缺失吞成普通执行失败，页面在还有未处理岗位时甚至会显示成功。现保留授权缺失原因码，记录已产生的失败轨迹数量，并让其他岗位仍可单独成功；网页同时显示已完成、失败和剩余数量。
- 需求评审页面与批量重算说明同步改为当前真实边界，避免提示用户确认费用后就可以调用在线模型。
- 后端全量回归 1641 项通过；全量测试启动后增加了这轮批量匹配保护与资料 HTTP 测试，最终新增路径另经针对性测试验证，不能把全量结果当成最终代码全覆盖。当前批量匹配入口仍支持每轮最多 10 个，而主工作台目标为每轮最多 5 个新增分析，尚需统一与契约迁移。

后续切片已将旧批量匹配的单轮上限统一为 5；细节与兼容性见 `P1-main-loop-batch-five-limit.md`。
