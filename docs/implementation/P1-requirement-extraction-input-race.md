# 岗位描述变化时保护要求提取

- 用户问题：提取正在处理岗位描述时，重新导入更新了描述；旧结果可能晚于新描述保存并成为最新提取，用户随后看到不适用的要求。
- 目标：保存前在同一 SQLite 短写事务中复核描述的标准化摘要；不一致则保留已有提取，明确提示检查岗位并重新分析。岗位状态检查同时保留。
- 不做：不自动重试模型、不删除历史、不承诺撤回已发出的请求；不绕开要求质量审核。该检查只保证保存时描述一致，之后的新导入仍通过已有过期检查处理。
- 契约：HTTP 409 `job_description_changed_during_extraction`；批量提取逐项返回同一错误码，继续其他岗位，模型调用计数标记为不完整；网页给出修复提示。
- 验证：隔离 SQLite 真实 HTTP 中，在替身提取期间改写描述，确认无新提取，已有提取保留；覆盖描述不变、批量隔离和网页提示。禁止使用收费模型与真实求职库。
- 设计决定：模型调用在事务外；描述摘要复核和写入在同一短事务内，避免检查后导入竞争，不以独立读取冒充原子保护。
- 面试口述：在保存边界检查输入快照，而非仅在任务开始时检查；外部调用的费用可能已经发生，需要明确呈现不确定性。

## 本轮验证和剩余边界

- 隔离 SQLite / 真实 HTTP：替身计算期间改写岗位描述，接口返回 409，提取总数不变、旧记录仍在；批量测试验证该项失败后其他项继续，且计数完整性为假。
- 浏览器使用合成数据，通过错误码回跳展示中文修复提示；这是提示渲染验证，不是浏览器内触发并发导入的端到端复现。
- 原有正常提取、失效标记及其计算期变更测试继续通过。已发送的调用不能撤回；本轮没有真实模型费用验收。
- 本切片只检查描述摘要和失效修订；同一描述下并发提取保护由后续 `P1-requirement-extraction-concurrency.md` 处理，来源质量元数据的并发变化仍未固定。审核基线连带失效的问题仍需单独解决。
