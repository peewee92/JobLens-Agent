# P1 · 本地正式产品与能力差距验收

用户要用本机启动的正式产品，不是预置样本站。此前的离线演示会拉起真正的前后端，但岗位提取使用样本规则，不能代表真实模型、真实资料授权或求职判断。保留演示作为独立入口。

| 确定问题 | 新需求与可观察验收 |
| --- | --- |
| 正式启动没有单命令，容易启动到演示 | 独立正式启动命令，默认空库、只监听本机、可恢复，不读演示库或原库。可显式使用已有模型配置（不把密钥传给前端）；没有模型也能手填资料。首页清楚显示当前是正式本地模式。 |
| 正式 PDF / 文字提取没有逐次调用入口 | 先在本机读取 PDF/DOCX，再显示服务及模型、最多一次请求和输出上限；要求用户确认才发送文字。未确认、改输入、重复请求或异常不得自动付费重发。返回的是可核对草稿，不自动保存为职业事实。 |
| 旧能力规划入口把已人工核对的岗位挡在内部质量流程外 | 用与个人匹配相同的岗位要求门禁。保留原文版本、完整性与人工确认条件，不改变正式模型质量审核口径；缺失或过期时给可执行入口，不要求求职者做质检。不得悄悄缩小范围。 |
| 差距页面没说清证据不足是否影响投递，以及怎么行动 | 说明差距是已确认经历的覆盖和当前目标，不是能力评分；区分含必需条件、非必需和要求未知。准备、补已做经历与学习不混同；明确归属于哪些岗位，绝不为用户补造经历。 |

真实请求仅在独立验收库，使用授权范围内的合成简历和脱敏岗位。首轮最多 5 次、人民币 5 元，不测连接消耗额度，不用真实个人资料。回归记录动作、预期、事实、修复和剩余问题；不能用离线结果代替实际调用、不能将自动操作称为真人试用。正向验收从冷启动、简历计划与人工确认、岗位提取与人工确认、比较、能力差距、准备、刷新；异常覆盖未授权、未配置、缺／过期岗位、重复和外部调用失败。

## 契约与边界

- 新增仅本机正式模式启用的 `/api/v1/local/profile-model/status`、`POST /plan`、`POST /file-plan`、`POST /calls`。`plan` 输入 `resumeText`，文件计划输入 `file`；计划返回 `planDigest / model / destination / inputCharacters / maxProviderCalls / maxOutputTokens`，不回传密钥或完整简历。调用输入沿用 `CallInput`，必须 `confirmed: true`、`maxProviderCalls: 1` 和最新摘要。同一请求标识只查询原回执，不重复发送。外部公开模式返回 404。
- 复用已有安全传输、结构化简历草稿与追踪。后台独占模型配置；输入变化需重做计划，网络中断不猜测“没有花费”。本机模式只允许真实已配置模型或关闭模型，不能偷偷用样本代替。
- 个人提取增加窄范围 `personal-skill-proof-v1`：原文明确要求单项技能并“说明”项目时，保留整段与重要性，避免当成无法比较的泛约束。抽取版本、计划摘要、追踪记录一起标记；不修改历史记录、不重写冻结模型验收规则，不推广成多项技能／年限／优先条件。
- 补证据、修复岗位的页面带回原差距岗位范围；只接受合法本地岗位标识，不接受任意返回网址。最多 50 个，不静默去掉岗位。
- 非中文模型解释保留可展开原文；不凭空伪造翻译，也不为了翻译追加收费调用。明确硬冲突会跳过召回，不能误标成“历史报告缺失，需重算”。

## 本轮可复现失败与技术取舍

同一份合成 PDF 在普通提取入口被禁止，但界面仍说不会调用在线模型；独立正式库的已人工确认岗位在旧 `/gaps` 又被 `accepted_baseline_missing` 阻断。修复为显式逐次授权和共用个人匹配门禁，保留原始证据、过期检查与内部质量评审，不能用关闭所有门禁来换“跑通”。批量导入还复现了首条回执过早预取只含一个岗位的链接：保存期间隐藏跳转，批次结束后再给完整范围。

## 面试口述（不虚构结果）

“我把样本演示和真实本地使用分开，在独立空库用合成资料真实调用已配置模型。通过屏幕操作发现并修复了授权、要求分类、质量门禁和范围丢失问题。真实模型输出仍需用户核对；我没有把模型判断当作职业事实或录用概率，也没有拿离线跑通冒充真实模型验收。”

本轮发现的流程阻断已修复。保留的产品边界：扫描图片简历尚不支持 OCR；模型误差仍须人工核对，不能承诺任意招聘原文都完整正确；不自动投递，不根据缺证据断言用户不会。后续优先收集真实使用反馈和更多脱敏 JD 做模型效果评估，而非扩大这次 5 次付费授权。
