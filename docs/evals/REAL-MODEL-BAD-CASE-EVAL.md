## 回归流程

1. **先冻结再归因。** 原文、合成证据和参考标签先于模型结果锁定。先检查正文是否截断，再检查候选集和确定性规则，最后核对模型的引用及结论。没有证据区分原因时标待核实，不靠重写提示词碰运气。
2. **先离线复现，再有限复测。** 为已定位的问题补上失败测试和反例。使用同一批输入、独立数据库复测；请求成功、结果校验通过、报告保存分别验收，限额或状态不明就停，不自动重试。
3. **最后验证已保存的结果。** 浏览器关闭模型，从报告历史打开指定版本并刷新，确认可重复读取，不把重新生成当成恢复。两轮仍过不了同一门禁就保留失败、记录排查结论，不无限补丁。

## 复现与人工抽检

从仓库根目录运行。`--dry-run` 不发送真实请求；`--render-report` 会重写这份 Markdown 的自动表格，执行前保留下方的人工复验记录，生成后再合并。

~~~sh
PY=services/backend/.venv/bin/python
EVAL=services/backend/scripts/eval_real_jds.py
DATA=data/private/real-jd-eval
$PY $EVAL --dry-run --samples "$DATA/samples.json" --run-dir "$DATA/new-offline"
$PY $EVAL --render-report --samples "$DATA/samples.json" \
  --offline-result "$DATA/V2-final-offline/result.json" --v1-result "$DATA/V1/rescored.json" \
  --v2-result "$DATA/V2-B/result.json" --review "$DATA/assisted-review.json"
~~~

真实模式需同时提供 `--confirm-live-llm`、`--round V1|V2`、私有 `--model-config` 和新的 `--run-dir`。
可用 `--backend-dir` 选择待验收代码；只读复核用 `--rescore`，不会重新发请求。
独立复核者在私有 JSON 按样本 ID 记录 `verified`、`cause`（四象限键或 `null`）、`phenomenon`，
可选填 `stage`、`repair`。V2 保存后用 `--v2-result` 合并；在双轮与人工抽检齐备前不更新 README 质量结论。
