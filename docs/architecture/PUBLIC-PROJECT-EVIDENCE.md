# 一页理解 JobLens：设计解决什么问题

```text
用户：确认背景、选择岗位、确认目标、记录行动
       ↓
Next.js 工作台（自然语言不是必经入口）
       ↓
FastAPI 单体：稳定业务工作流
       ├─ 模型：资料／要求提取，必要的语义判断
       ├─ 规则：硬条件、证据约束、事实版本、预算与权限
       ├─ Agent：在已授权范围识别意图，组合已有工具
       └─ 人工确认、持久运行与恢复：应用层承担
       ↓
SQLite：事实、报告、历史分析、工作区与行动
```

公开部署额外增加请求级临时数据库隔离，不等于完整多租户服务。MCP 只是已有只读业务的协议接入，不是第二套业务核心。

## 三个问题与工程证据

| 问题 | 设计取舍 | 失败与测试入口 |
| --- | --- | --- |
| 怎么防止编造职业经历？ | 要求与确认经历统一结构化，建议引用证据；缺证据不是确定不会 | `test_insufficient_evidence_flow.py`、`test_three_job_journey.py` |
| 重试为什么不能偷偷重复付费或覆盖结果？ | 固定输入、请求身份、调用记录、独立历史；未知结果不伪报成功 | `test_authorized_requirement_call.py`、`test_authorized_semantic_call.py`、持久运行测试 |
| 做完行动是否就代表掌握技能？ | 行动只是进度，成果要另行确认后才能成为职业事实 | `test_action_feedback_journey.py` |

## Agent 的价值与边界

稳定按钮流程是默认。模型负责理解，规则负责约束，Agent 只组合现有工作流，不能新造职业事实、自动投递或扩大岗位范围。

LangGraph 当前执行排序图编排；人工确认、检查点和恢复由应用层实现，不能包装成已采用原生 interrupt/resume。框架存在不等于自主 Agent 有收益。

六个固定对比任务：

1. 对明确岗位批次排序。
2. 对指定岗位生成准备方向。
3. 已有足够事实时直接说明，不调用工具。
4. 指代不明时先澄清。
5. 请求范围外的岗位时拒绝扩大范围。
6. 请求不支持的能力时明确边界。

比较显式流程与自然语言入口的任务成功、工具选择、耗时、调用量、费用和人工求助。**当前真实模型对比未执行，不能声称 Agent 优于工作流。**复用 `career_tool_selection`、`career_trajectory` 和 `career_loop_latency` 评估，不另建框架。

可运行的六类契约示例：在后端目录执行 `.venv/bin/python -m scripts.demo_agent_evidence`。它复用冻结意图回放，输出成功和拒绝轨迹，零模型、零业务写入；只证明约束，绝不证明真实意图理解准确率或效率收益。

## 面试表达

- AI 全栈：从资料到岗位比较、准备行动的可运行链路，加上公开演示隔离、异常恢复和部署边界。
- Agent 开发：受约束工具选择、证据来源、人工确认、恢复与分层评估；对没有收益的任务保留确定性流程。
- 不声称：匹配分数是概率、提高真实录用率、已有生产多用户系统、合成结果代表真实模型质量。
