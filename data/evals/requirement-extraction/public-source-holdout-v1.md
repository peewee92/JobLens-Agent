## 验收口径

- 标签是发布文本的预先参考答案，未经过第二人复核，并不覆盖一份 JD 的所有条件；自动断言外的替代关系、边界句与约束必须另外核对。
- 评估分开记录：句子引文在不在输入中、明确条件是否漏掉、重要性和替代关系是否篡改、有没有无中生有。记录逐样本结果而不是用小样本通过率替代总体质量。
- 2026-11-18 完成四条真实在线调用与逐条核对，详见 [真实模型复验记录](../../../docs/implementation/P1-first-use-feedback.md#2026-11-18--真实模型复验4-条脱敏公开岗位)。范围仅做岗位要求提取，不包括简历与个人匹配。

### 可重复的只读验收

目标是从独立 SQLite 对照实际保存的提取，而不是调用模型或复制期望答案。验收输入为本清单的四条改写、它们的岗位标识与原文 SHA-256，以及模型请求回执和保存结果。正式十条门禁不变。脚本会区分未测、请求失败或未确定、回执与提取不一致、以及完成后发现的漏项、重要性冲突或无原文依据。必须用外部传输记录确认是在线结果还是模拟回放；数据库本身无法证明网络目的地。即使所有自动断言通过，也需独立核对表格中的替代条件和资格约束。

在 `services/backend` 下运行（只读，不会产生推理费用）：

```bash
python -m scripts.review_public_requirement_holdout --db /path/to/holdout/local.db --manifest /path/to/holdout/manifest.json
```

清单是 JSON 数组，每条含 `caseId`、导入响应中的 `jobId`、原文 UTF-8 的 `descriptionSha256`。每轮用新的隔离库，每条只允许一个显式授权回执；已失败、不确定或同岗多份回执都不会退回到旧结果来算分。脚本返回 0 只表示四条已保存结果的预设标签检查通过；1 表示仍有未测、不一致或标签问题；2 表示输入无法读取或不支持。在线结论需结合请求运行日志及逐条人工复核，不能单凭脚本返回码。
