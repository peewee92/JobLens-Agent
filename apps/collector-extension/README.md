# 岗位筛选 v1.4.9

一个运行在已登录 BOSS 直聘 Chrome 会话中的通用岗位搜索、采集、筛选与导出工具。

产品名称不再限定为“AI 岗位整理器”。**AI/大模型只作为默认关键词模板和功能说明中的一个使用场景**：你可以把关键词替换为前端、产品、实施、交付、解决方案、FDE、销售或任何其他岗位。

插件支持多城市搜索、全国远程识别、BOSS 私有字体薪资解码、薪资/相关度/招聘者活跃度过滤、详情补采、JD 质量分级、去重统计，并导出 CSV、完整报告 JSON、诊断 JSON 与 JobLens Requirement 验收数据集。

## v1.4.9：招聘者活跃度与疑似僵尸岗位过滤

- 新增「招聘者最近多久活跃」主筛选项，支持不限制、60 天、30 天、14 天、7 天，默认 30 天；
- 列表卡片与详情页都会识别招聘者活跃信号，包括 `刚刚活跃 / 今日活跃 / 本周活跃 / 近两周活跃 / 本月活跃 / N天内活跃 / N月内活跃 / N月前活跃 / 半年前活跃 / N年前活跃`；
- 对“30 天内”这类窗口采用保守语义：只有能确认招聘者在窗口内活跃才保留；例如 `2月内活跃` 不能证明 30 天内活跃，因此不会被当作 30 天内岗位；
- 卡片无法判断活跃时间时不会立刻当作僵尸岗位，而会优先进入详情页补采；详情仍无法确认时才按“招聘者活跃状态未知”过滤；
- 详情补采优先级新增招聘者活跃待确认队列，避免这类候选被普通 JD 补采挤出详情额度；
- 诊断 JSON、统计和 CSV 新增招聘者活跃原文、估算时间范围及详情补采数量，便于解释岗位为什么被过滤；
- 该信号用于提高“值得优先投递”的岗位新鲜度，不把招聘者长期未活跃直接等同于岗位绝对失效；需要最大召回时可选择“不限制”；
- Collector 报告版本升级为 `1.4.9`，JobLens Backend 同时兼容 `1.3.1` 至 `1.4.9`。

## v1.4.8：筛选项产品化与“结果偏少”解释

- 将“最低薪资 K / 薪资过滤方式 / 详情补采范围 / 翻页策略”等偏工程化名称改成普通用户能直接理解的问法；
- 每个关键筛选项增加 `?` 帮助说明，支持鼠标悬停和键盘聚焦查看具体含义与示例；
- 新增“当前实际覆盖范围”，明确“全国远程”只补充全国远程岗位，不等于搜索全国所有线下岗位；
- 新增“结果可能偏少的原因”动态诊断，根据城市数、每词页数、薪资严格模式、相关度门槛、远程确认、详情上限和主动排除项实时解释当前配置；
- 普通用户无需理解所有高级采集参数：界面明确标出前 5 项是主要筛选条件，其余采集与远程设置默认即可；
- Collector 报告版本升级为 `1.4.8`，Backend 同时兼容 `1.3.1` 至 `1.4.8`。

## v1.4.7：相关度改为以用户搜索词为主

- 修复“插件支持任意岗位关键词，但相关度评分仍硬编码偏向 AI/研发岗位”的不一致；
- 标题直接命中用户搜索词时给予高相关度，像 `视觉设计 / 平面设计 / UI设计` 这类非 AI 岗位不再被错误过滤；
- 对 `餐饮设计 → 餐饮空间设计师`、`教育设计 → 教育-UI设计/视觉设计师` 这类“领域词 + 岗位词”组合进行有限的标题意图匹配；
- `解决方案专家（教育行业）` 这类只碰到“教育”但没有“设计”意图的岗位，不再仅因为“解决方案”字样达到默认相关度阈值；
- 原有 AI/大模型/Agent 分类评分继续保留，兼容默认 AI 岗位模板；
- Collector 报告版本升级为 `1.4.7`，Backend 同时兼容 `1.3.1` 至 `1.4.7`。

## v1.4.6：补齐 CJK 部首文本规范化

- 真实数据验收发现整页辅助文本中仍可能残留 CJK Radicals Supplement 字符，例如 `⻓`（U+2ED3）；
- 文本规范化现在覆盖 `U+2E80–U+2FD5`，并对已观测的 `⻓` 显式映射为普通汉字 `长`；
- 该修复同时作用于卡片文本、JD 正文与整页辅助文本，不改变原始 `JobSource.source_raw` 的留存策略；
- Collector 报告版本升级为 `1.4.6`，Backend 同时兼容 `1.3.1` 至 `1.4.6`。

## v1.4.5：远程语义与 JD 文本规范化

- 远程识别不再读取包含推荐职位、页脚和全站内容的 `detailText`，只使用标题、卡片字段、地点标签和已裁剪的 JD 正文；
- `远程支持 / 远程监测 / 远程控制 / 远程运维` 等业务语义不再等同于远程办公，避免 FDE、设备和安防岗位被误标为远程；
- 标题中的 `全远程 / 全国远程 / 兼职远程`、正文中的 `可远程 / 远程办公 / 居家办公` 继续作为明确证据；
- JD 文本会把康熙部首和 CJK 兼容字规范为普通汉字，并移除零宽空格，避免技能识别、近重复判断和 evidence span 被视觉相同但编码不同的字符干扰；
- Collector 报告版本升级为 `1.4.5`，Backend 同时兼容 `1.3.1` 至 `1.4.5`。

## v1.4.4：岗位证据内容门禁

- `full_jd` 除了长度、来源和页面噪声外，现在还必须包含可用于 Requirement Extraction 的岗位职责或任职条件证据；
- 有标准“岗位职责 / 任职要求 / 任职资格”等标题的 JD 可直接满足内容门禁；无标准标题时，必须同时具备足够的职责动作与任职条件，或形成强编号职责/要求结构；
- 纯公司简介、业务宣传、团队荣誉和发展历程不再因为文本较长、存在编号或出现“开发/经验”等泛化词而被误判为 `full_jd`；
- 新增 `descriptionHasRoleEvidenceSignal / descriptionResponsibilitySignalCount / descriptionRequirementSignalCount`，完整报告、诊断和 CSV 可追踪内容门禁依据；
- 详情正文开头孤立的 `】`、`]` 等闭合符号会被清理，减少 evidence span 的格式噪声；
- 远程识别会先剥离“不接受居家办公 / 不支持远程办公 / 非全远程”等否定短语，再判断剩余正向证据；`全国远程` 作为高置信度证据；
- diagnostics 的 `remoteConfirmed` 统一表示最终岗位，新增 `candidateRemoteConfirmed` 表示全部候选中的远程命中，避免跨口径同名统计；
- Collector 报告版本升级为 `1.4.4`，Backend 同时兼容 `1.3.1 / 1.4.0 / 1.4.1 / 1.4.2 / 1.4.3 / 1.4.4`。

## v1.4.3：正式验收详情配额

- `matched` 详情模式不再只为已通过岗位预留 20 个名额，而是按正式样本数的 1.5 倍预取，默认 40 个详情名额中优先安排 30 个已通过岗位；
- 剩余详情名额继续用于全国远程候选，默认最多 10 个，避免大量最终被判定为非远程的岗位挤占 Requirement 验收数据；
- 标题仅空格或标点不同、且公司/地区/薪资相同的卡片会延后补采，减少明显重复岗位消耗详情名额；
- 完整报告与诊断新增 `detailTargetsPlannedAccepted / detailTargetsPlannedRemoteCandidates / detailTargetsDeferredAccepted`，可追踪详情配额去向；
- 20 条独立完整 JD 门槛、近重复阈值和 `blocked` 行为保持不变，不通过放宽质量标准凑数；
- Collector 报告版本升级为 `1.4.3`，Backend 同时兼容 `1.3.1 / 1.4.0 / 1.4.1 / 1.4.2 / 1.4.3`。

## v1.4.2：独立样本与招聘者尾部治理

- 可信 JD 节点也会清除招聘者姓名、活跃状态、公司和 HR 身份尾部；
- 清理后不足 180 字的 JD 会重新降级，不会因招聘者信息凑够长度；
- Requirement 验收样本会按 JD 正文近似度去重，同一职位被不同猎头或公司重复发布时只保留一个代表样本；
- `qualityGate` 新增 `distinctEligibleCount / nearDuplicateCount`，只有 20 条独立完整 JD 才标记为 `ready`；
- 导出新增 `selectionPolicy / excludedNearDuplicates`，记录近重复阈值、被排除岗位及代表岗位；
- `detailCohort*` 改为按唯一职位 URL 计数，避免跨城市/远程搜索范围重复统计；
- Collector 报告版本升级为 `1.4.2`，Backend 同时兼容 `1.3.1 / 1.4.0 / 1.4.1 / 1.4.2`。

## 默认关键词只是模板

首次安装仍会预填一组 AI/大模型方向关键词，这是为了让插件开箱即可使用，也是一个典型使用场景。你可以全部删除并换成自己的目标岗位，例如：

```text
高级前端开发工程师
前端架构师
Electron 开发工程师
产品经理
解决方案工程师
实施工程师
交付工程师
```

插件不会根据产品名称强制岗位必须包含 `AI`。实际搜索范围完全由“搜索词”输入框中的内容决定。

## 城市选择

- 默认选择武汉；
- 支持中国大陆 31 个省级地区、368 个城市/地区；
- 采用“已选城市 + 热门城市 + 省份导航 + 城市网格 + 城市搜索”的选择方式；
- 支持同时选择最多 20 个城市，插件会分别执行搜索；
- “全国远程”是独立搜索范围，可以与任意城市组合；
- 自动保存最近选择的城市。

> 省份用于组织和查找城市，不代表一次请求覆盖整个省。BOSS 搜索 URL 使用具体城市编码。

## 搜索任务计算

```text
搜索任务数 = 搜索词数量 ×（已选城市数量 + 是否启用全国远程）
最大页面数 = 搜索任务数 × 每个搜索词页数
```

选择过多城市和关键词会显著增加访问次数，插件会实时显示预计任务规模。

## 主要能力

- 任意岗位关键词搜索，不限定 AI 岗位；
- 多城市批量搜索，默认武汉；
- 全国远程卡片识别与详情页确认；
- 解码 BOSS 私有字体薪资；
- 多来源薪资提取和动态数字映射；
- 按薪资阈值、岗位相关度、招聘者最近活跃时间和兼职/实习/助理条件筛选；
- 岗位分类、技能、城市、公司、搜索词贡献等统计；
- 稳定去重并记录重复命中次数；
- 异常时自动导出错误现场 JSON；
- CSV、完整报告 JSON、诊断 JSON 和 Requirement 验收数据集自动下载；
- 完整 JD 质量分级与 20 条正式验收门禁。

## 安装或升级

1. 解压 `boss-job-filter-extension-v1.4.9.zip`。
2. Chrome 打开 `chrome://extensions/`。
3. 开启“开发者模式”。
4. 删除或停用旧版，避免同时存在多个版本。
5. 点击“加载已解压的扩展程序”。
6. 选择解压后的 `boss-job-filter-extension-v1.4.9` 文件夹。
7. 确认插件显示名称为 `岗位筛选`，版本为 `1.4.9`。

## 安全与限制

- 插件不会绕过验证码或安全验证；遇到验证需要人工完成。
- 请控制搜索规模和运行频率。
- BOSS 页面结构可能变化，真实页面选择器和字段仍需在本机登录环境中验证；`body_fallback` 不会被当成正式 JD。
- Requirement 正式人工质量验收需要 20 条独立 `full_jd`；详情页读取成功数、合格岗位记录数和独立 JD 样本数是三个不同指标。
- 插件只读取职位搜索和详情页面，不会自动投递或发送消息。
